## Какие задачи предстоит решать в команде

Модуль планирования: каждый цикл (десятки мс) строит траекторию для
эго-мобиля по состоянию окружения. Типичная работа:

1. **Горячие пути.** Построение траекторий, поиск по объектам, выбор
   сценариев выполняется 10^6–10^8 раз. Лишний O(log n) или копия вектора
   измеряется миллисекундами и секундами. => Задачи 1, 2, 3, 5.
2. **Кинематика.** Траектории, интерполяция, выбор точки по времени,
   кумулятивные длины. => У тебя уже есть `practice/trajectory_perf` —
   это полноценная «продовая» задача такого типа.
3. **Передача данных между модулями (IPC).** Прогноз присылает партии
   траекторий планировщику. Данные переносят MOVE'ом, а не копией:
   10^6 точек = десятки мегабайт на партию. => Задача 4.
4. **Монте-Карло / симуляция.** Сэмплирование поведения объектов по
   вероятностям. 10^7–10^8 сэмплов в секунду — нужен O(1)-сэмплер. => Задача 1.
5. **Ранжирование и поиск.** Пересечение топов, скоринг — хеши,
   сортировка, два указателя. => Задача 3.
6. **Текст.** Телеметрия, логи, дамп отладки: O(n) по строке без
   квадратичных копий. => Задачи 2, 6.
7. **Тесты ДО фикса.** Тест (включая перф-тест с бюджетом) находит дефект,
   потом фикс. Красное -> зелёное. Формат работы в этой папке ровно такой.

## Формат работы (как в practice/)

1. Прочитай `README.md` внутри задачи.
2. **Устно** — подход и сложность (я спрашиваю как интервьюер:
   структура данных, O(...), граничные случаи).
3. Напиши тесты в `main.cpp` (счётчик failures, `return failures`).
4. Скомпилируй и прогони на LEGACY-заголовке:
   `g++ -std=c++17 -Wall -Wextra -O2 main.cpp -o t && ./t`
   — «красное» ожидаемо (ошибка компиляции / превышение бюджета).
5. Починь заголовок. Зелёное.
6. Сдаёшь: «готово» + полный вывод `./t` (или текст ошибки компиляции).

`reference/` внутри каждой задачи — эталонное решение с тестами.
Не смотри до «готово». Застрял — сначала обсудить со мной, потом заглянуть
конкретно в ту часть, где застрял.

## Типовые вопросы ревьюера команды (готовься отвечать устно)

- Почему `noexcept` на move? (реаллокация vector -> relocation, а не copy)
- Почему frame — `shared_ptr`, а кэш — `unique_ptr`?
- Что с moved-from объектом и кто отвечает за контракт?
- Худший случай `unordered_set` и как застраховаться (reserve, max_load_factor).
- O(n) vs O(n log n): когда разница важна? (10^6 vs 10^7 сэмплиров в секунду)
- Почему вернуть `by value`, а не `const&`, если есть кэш?
- Потокобезопасность ленивого кэша (mutex + double-checked).
- Почему `Add(T)` принимает by value + move, а не `const&` или `T&&`?
