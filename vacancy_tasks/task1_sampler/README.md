# Task 1. AliasedSampler — O(1)-сэмплирование дискретного распределения

## Контекст (что это в команде)

Монте-Карло-симулятор сценариев: на каждом шаге для каждой машины
окружения сэмплируется «поведение» (тормозит / перестраивается / держит
скорость) с заданными вероятностями. Кадр: 100 машин x 100 копий
сценария = 10^4 сэмплиров; симуляция 10^3 кадров/с -> **10^7 сэмплиров/с**.
Текущая реализация (`sampler_legacy.h`): CDF + `lower_bound` — O(log n)
на сэмпл. Для n = 10 «терпимо», но в профилере это шумит.
Требование: **Sample() — O(1) без выделений**, конструктор — O(n).

## Решение: Walker's Alias Method (понять ПЕРЕД кодом!)

n «корзин», каждая ёмкостью 1. Значение с нормированной вероятностью
p_i (sum = 1) получает «долю» n * p_i корзин:
- если n*p_i < 1 — значение занимает долю корзины, её «недолив»
  (1 - n*p_i) должен покрыть кто-то другой;
- если n*p_i > 1 — значение занимает корзину целиком и «лишним»
  закрывает недолив лёгких значений: `alias_[лёгкий] = тяжёлый`.

Сэмплирование: basket b — равномерно [0, n), монетка u — равномерно
[0, 1): u < prob_[b] -> values_[b], иначе values_[alias_[b]].
Обе выборки O(1), выделений нет.
**Докажи устно:** ожидаемая вероятность значения = p_i.

Почему не «таблица частот» (вектор из sum 1/p_i ячеек)? При p_i = 1e-6 —
миллион ячеек, память взрывается. Почему не таблица квантилей? То же.

## ТЗ

Реализовать `AliasedSampler` в `sampler.h` (скелет с TODO):

- конструктор — O(n), память O(n);
- `Sample()` — O(1) в среднем, без выделений в горячем пути;
- валидация (бросать `std::invalid_argument`):
  - пустые `values` / `weights`;
  - несовпадение размеров;
  - вес <= 0, NaN, Inf;
  - сумма весов не конечна (переполнение до Inf);
- move: исходник валиден, но пуст; `Sample()` на исходнике —
  `std::logic_error` (защита от UB: `uniform_int_distribution(0, -1)` — UB);
- сложности — в комментарии над конструктором и `Sample()`.

## Тесты (минимальный набор, в main.cpp)

a) детерминизм: одинаковый seed -> одинаковая последовательность;
   разный seed -> (почти surely) разная;
b) частоты: weights {1,3,5} -> {1/9, 3/9, 5/9}, N = 10^6, допуск 0.015;
c) одно значение: всегда оно;
d) валидация: пустые, разные размеры, вес 0, отрицательный, NaN, Inf —
   все `std::invalid_argument` (try/catch на каждый подкейс);
e) move: dst сэмплирует нормально; src -> `std::logic_error`;
f) PERF: n = 1000, N = 10^7 сэмплов, бюджет 300 мс (`steady_clock`);
g) огромные веса {1e12, 1.0}: напечатай, сколько раз выпало значение 2
   (теоретически ~0–2 из 10^6). Сравни ментально с CDF-подходом:
   почему CDF-вариант здесь вырождается хуже/лучше?
