# Яндекс C++ Guidelines для собеседований

При проверке кода кандидата строго оценивай следующие аспекты:

1. **Управление памятью и умные указатели**:
   - Запрети использование `new`/`delete` без крайней необходимости.
   - Требуй использования `std::unique_ptr` для эксклюзивного владения и `std::shared_ptr` только при реальном разделении владения.
   - Проверяй понимание `std::move` и семантики перемещения. Если объект больше не нужен, его ресурсы должны быть перемещены, а не скопированы.

2. **Передача аргументов**:
   - Примитивы (`int`, `double`, `bool`) передавать по значению.
   - `std::string`, `std::vector` и другие тяжелые объекты передавать по `const&` (если не планируется их модификация или перемещение внутрь).
   - Если функция забирает владение объектом, аргумент должен быть `T&&` или `T` с последующим `std::move`.

3. **Константная корректность**:
   - Все методы, не изменяющие состояние объекта, должны быть помечены `const`.
   - Ссылки на данные, которые не должны меняться, должны быть `const&`.

4. **Сложность алгоритмов**:
   - Всегда требуй от кандидата устную оценку Time Complexity и Space Complexity перед или сразу после написания кода.
   - Для Medium задач ожидаемое время: $O(N)$ или $O(N \log N)$, память: $O(1)$ или $O(N)$.

5. **Граничные случаи (Edge Cases)**:
   - Пустые входные данные, нулевые значения, очень большие числа (переполнение `int`), дубликаты.
