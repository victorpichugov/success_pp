## 1. Исправления к прошлой лекции

В 9-й лекции осталось неаккуратное место:

```cpp
template<class T, class Z>
void f(T& x, Z& y);
```

Вызов `f(1, 2)` для такой сигнатуры **не компилируется**: `T&`/`Z&` — это **левые** ссылки,
а `1` и `2` — **правые** (временные) значения, с которыми левые ссылки не связываются.

Лечится снятием «лишних» `&` (или заменой на `const&`) — и всё работает:

```cpp
template<class T, class Z>
void f(T x, Z y);              // по значению — f(1, 2) OK

template<class T, class Z>
void f(const T& x, const Z& y);  // по const-ссылке — f(1, 2) тоже OK
```

> Правило: `const T&` принимает **всё** (lvalue, rvalue, const) — самый универсальный параметр
> шаблона, когда копировать жалко, а менять не надо.

## 2. Шаблоны с переменным количеством параметров (variadic templates)

По аналогии с функциями с переменным количеством аргументов (`printf(...)`), **только типобезопасно**.
Это очень неприятная вещь с шаблонами — синтаксис громоздкий, но другого способа нет.

### 2а. Parameter pack

```cpp
template<typename... Args>   // Args — «пакет» шаблонных аргументов
void f(Args... args);        // произвольное количество аргументов произвольных типов
```

Многоточие `...` читается так: **«повтори паттерн»**.

- в `template<typename... Args>` повторяется `typename` — получаем список типов;
- в `void f(Args... args)` повторяется `Args` — получаем список параметров, каждый своего типа.

### 2б. Пример: `print`

Рекурсия по пакету: откусываем по одному аргументу, пока пакет не станет пустым.

```cpp
void print() {}                       // базовый случай: аргументов нет

template<typename Head, typename... Tail>
void print(Head x, Tail... t) {
    std::cout << x;
    print(t...);                      // «раскрыть» пакет: print(t1, t2, ..., tn)
}

print(1, 2.5, 'a');                   // печатает 12.5a
```

Как разворачивается вызов:

```
print(1, 2.5, 'a')  →  Head = int,    Tail = {double, char}
print(2.5, 'a')     →  Head = double, Tail = {char}
print('a')          →  Head = char,   Tail = {}      (пусто)
print()             →  базовый случай
```

> Без пустой перегрузки `print()` код **не скомпилируется**: на последнем шаге вызывается
> `print()` с пустым пакетом, и под него должна существовать функция.

### 2в. `sizeof...` — сколько аргументов в пакете

Количество элементов пакета известно **на этапе компиляции**:

```cpp
template<typename Head, typename... Tail>
void f(Head& x, Tail&... t) {
    std::cout << sizeof...(t);   // константа: 0, 1, 2, ...
    f(t...);
}
void f() {}
```

### 2г. Пакет в типах: `C<Tail>...`

Многоточие работает и в **типах** — паттерн повторяется для каждого элемента пакета:

```cpp
template<typename... Tail>
void f(C<Tail>... t);   // C<T1> t1, C<T2> t2, ... — тип Tail у всех аргументов
```

Три места, где `...` встречается постоянно:

| Запись | Что делает |
|---|---|
| `typename... Args` | объявить пакет **типов** |
| `Args... args` | создать параметры **по одному на каждый тип** |
| `f(t...)` / `C<Tail>...` | **раскрыть** пакет (подставить все элементы) |

### 2д. Где это применяется

- `std::pair<T, U>` — упорядоченная пара (упражнение: реализовать самому);
- `std::tuple<T, U, V, ...>` — кортеж: **произвольной длины** набор разнотипных значений.

```cpp
std::tuple<int, double> t;
t.get<1>()   // верни элемент по номеру (0, 1, 2, ...)
t.get<int>() // верни элемент по типу (C++14: std::get<int>(t))
```

> **Задание из лекции:** реализуйте простейший аналог класса `tuple` (задание сложное):
> хранение N разнотипных полей + `get<I>()` по индексу + `get<T>()` по типу.
> Строится ровно на рекурсии по пакету: `tuple<Head, Tail...>` хранит `Head` и `tuple<Tail...>`.

## 3. Функторы

**Функтор** — объект, который можно **вызвать как функцию** (у него переопределён `operator()`).

**Компаратор** — объект, который поддерживает вызов себя с двумя аргументами, и этот вызов
означает **сравнение**.

### 3а. Компаратор в `sort`

```cpp
template<typename T, typename Cmp>
void sort(T* begin, T* end, Cmp cmp)   // begin, end — два указателя на массив
{
    ...
    cmp(*x, *y);   // может быть и функция, и объект
}
```

`cmp` — **функтор**. Именно так это написано в STL: стандартная сортировка принимает
компаратор третьим параметром. Круглые скобки (в отличие от квадратных) **можно перегружать**.

```cpp
std::sort(v.begin(), v.end());                 // по умолчанию — operator<
std::sort(v.begin(), v.end(), std::less<int>());
std::sort(v.begin(), v.end(), MyCmp());        // свой компаратор
```

### 3б. `std::less<T>`

Класс, в котором определён `operator()`:

```cpp
template<class T>
struct less {
    bool operator()(const T& x, const T& y) const {
        return x < y;
    }
};
```

`struct`, а не `class` — чтобы не писать `public` («а нам лень»). Для `greater<T>` — то же самое,
только `x > y`.

### 3в. Свой компаратор

```cpp
struct ByAbs {
    bool operator()(const int& x, const int& y) const {
        return std::abs(x) < std::abs(y);
    }
};

std::sort(v.begin(), v.end(), ByAbs());
```

Компаратор — обычный объект, поэтому у него могут быть **поля-настройки**:

```cpp
struct ByField {
    int key;
    explicit ByField(int k) : key(k) {}
    bool operator()(const Item& a, const Item& b) const { return a.f[key] < b.f[key]; }
};
```

> Компаратор должен задавать **строгое слабое упорядочение**: `cmp(a, a)` всегда `false`,
> `cmp(a, b)` и `cmp(b, a)` не могут быть истинными одновременно. На «нестрогом»
> компараторе (`<=`) `std::sort` падает.

### 3г. Чем функтор лучше указателя на функцию

- **состояние**: у функтора есть поля (указатель на функцию — «голая»);
- **скорость**: тип компаратора — параметр шаблона → вызов **инлайнится**, нет косвенного
  вызова через указатель. Поэтому `sort` с лямбдой/функтором быстрее, чем с `qsort`-указателем.

## 4. CRTP (Curiously Recurring Template Pattern)

Паттерн. Выглядит как бред, но надо разобраться.

```cpp
template<class T>              // шаблонный класс
struct Base {
    void f() {
        static_cast<T*>(this)->f();   // версия 1
    }
};

struct Derived : public Base<Derived> {   // «бред»: Derived наследуется от Base<Derived>
    void f() {}                          // версия 2
};

Derived d;
Base<Derived>* b = &d;
b->f();   // вызовется ВТОРАЯ f — из Derived
```

### 4а. Почему это работает

Внутри `Base<T>` тип `T` **известен на этапе компиляции**. Когда пишут `Base<Derived>`,
`this` (тип `Base<Derived>*`) кастуется к `Derived*` — и вызывается `Derived::f()`,
**без `virtual`, без vtable**.

> Это **имитация виртуальных функций без слова `virtual`** — так называемый
> **статический (шаблонный) полиморфизм**.

| | `virtual` | CRTP |
|---|---|---|
| Когда решается «какая `f`» | на этапе **исполнения** (vtable) | на этапе **компиляции** |
| Наценка | vptr + непрямой вызов | нет (вызов инлайнится) |
| Хранение в контейнере | `vector<unique_ptr<Base>>` | нельзя — все объекты разного типа |

### 4б. Требования и подводные камни

- `T` **обязан** быть классом, унаследованным от `Base<T>`, и обязан **сам** определить `f()`,
  иначе `static_cast<T*>(this)->f()` — ошибка компиляции;
- писать `Base* b = d;` нельзя — `Base` **не** является базой `Derived` по себе, база —
  конкретный `Base<Derived>`;
- если в `Derived` имя `f` скрыто, рекурсия `Base::f → Derived::f → Base::f` уйдёт в
  бесконечную рекурсию (типичная ошибка в CRTP).

### 4в. Зачем это нужно

- **считать объекты** класса: счётчик в `Base<T>` работает для каждого `T` отдельно;
- **подмешивать операторы** (`+=`, `++`, арифметику) в класс, не переписывая их;
- интерфейсы «без виртуальных вызовов», fluent API;
- в стандартной библиотеке: **`std::enable_shared_from_this<T>`** — готовый пример CRTP
  (`struct enable_shared_from_this` + наследование от самого себя как параметра шаблона).

## 5. Глава 7. Исключения: зачем они нужны

### 5а. `new` и нехватка памяти

```cpp
int* p = new int[1000];   // динамически выделяем память
```

Взяли **слишком много** у операционной системы, а она не может дать — **что делать**?
Функция не может вернуть «неудачу» значением указателя всегда, и `nullptr` — лишь частичное
решение (работает только для «указательных» мест):

```cpp
int* p = new (std::nothrow) int[1000];   // вернёт nullptr — проверять вручную
```

Обычный же `new` при нехватке памяти **бросает исключение** `std::bad_alloc` — и код,
который не проверял указатель, всё равно корректно «сломается».

### 5б. `dynamic_cast`

Тот же мотив: как сообщить о провале каста?

```cpp
Base b;
Derived& d = dynamic_cast<Derived&>(b);   // объект на самом деле Base → бросит std::bad_cast
```

- `dynamic_cast` для **указателей** → при провале `nullptr` (нужна проверка);
- `dynamic_cast` для **ссылок** → `nullptr` выдать нечем, поэтому **`throw std::bad_cast`**.

> Общий вывод: механизму, который умеет **прервать** выполнение и передать сигнал «я не могу»
> наверх, нужен язык. Это и есть `throw` / `try` / `catch`.

## 6. Синтаксис: `throw`, `try`, `catch`

```cpp
try {
    // код
} catch (int x) {
    // если бросили int — попадём сюда, x == брошенное значение
} catch (...) {
    // любой тип
}
```

Семантика:

1. начинаем выполнять код внутри `try`;
2. если в ходе выполнения **кто-то сделает `throw`**, текущее выполнение прерывается;
3. поднимаемся вверх по стеку вызовов в поисках **подходящего** `catch`;
4. найден **первый подходящий** — выполняется его тело, дальше по списку не смотрим.

```cpp
void f() {
    throw 5;          // бросаем int
}

int main() {
    try {
        f();
    } catch (const std::exception& e) {   // std::exception — общий «базовый» класс исключений
        std::cout << e.what();
    } catch (int x) {
        std::cout << x;
    } catch (...) {
        std::cout << "неизвестно что";
    }
}
```

> Бросать можно **что угодно** (в том числе `int`, `char*`) и **по значению**; ловить принято
> **по `const`-ссылке** — `catch (const std::exception& e)`, чтобы не срезать производный класс.

## 7. Исключения ≠ runtime error

**Не каждое исключение — это runtime error, и не каждый runtime error — это исключение.**

- **Исключение** — это то, что создаётся `throw` (явным в моём коде или неявным в библиотеке:
  `new` → `bad_alloc`, `at()` → `out_of_range`, `stoi` → `invalid_argument`).
- Взял массив на 100 элементов и обратился к 1000-му — это **не исключение**, а
  **runtime error** (точнее — UB): ничего не бросается, ловить нечего.

```cpp
int a[100];
std::cout << a[1000];   // НЕ исключение → NOT CATCHABLE (UB)
std::cout << a.at(1000); // std::vector::at → бросит std::out_of_range → ловится
```

> **UB — НЕ ПОЙМАТЬ.** `catch` не спасает от обращения по «мусорному» указателю,
> выхода за границы, гонки данных. Исключения — про **ожидаемые** и **объявленные** ситуации.

## 8. Порядок обработки исключений (вопрос на собеседовании)

```cpp
try {
    ...
} catch (double d) {
    std::cout << 2;
} catch (int x) {
    std::cout << 3;
} catch (...) {}
```

**Вопрос:** бросил `int` — напечатается `2` или `3`?

**Ответ:** напечатается **только `2`**. Выбор идёт по **первому подходящему** `catch`,
а `int` → `double` — допустимое неявное преобразование, поэтому первая ветка подходит.
Ветка `catch (int)` не выполняется **вообще**, до неё не доходит.

Отсюда правило порядка `catch`:

- от **частных** типов к **общим**;
- `catch (...)` — всегда **последним** (иначе всё после него мертво);
- иерархию исключений тоже надо сортировать: сначала потомки, потом `std::exception`,
  и только потом `...`.

```cpp
try { ... }
catch (const std::bad_alloc& e) { ... }        // частный
catch (const std::exception& e) { ... }        // общий
catch (...) { ... }                            // совсем всё
```

## 9. Продолжение главы (что лежит за границами лекции)

Лекция обрывается на правилах выбора `catch`. Дальше по главе 7 обычно идут:

- **Stack unwinding** — при подъёме к `catch` уничтожаются все локальные объекты на пути
  (вызываются деструкторы). Отсюда **RAII**: ресурсы держим в объектах, чьи деструкторы
  их освобождают — тогда утечки при `throw` нет.
- **`std::exception`** — базовый класс: `logic_error`, `runtime_error`, `bad_alloc`,
  `bad_cast`, `out_of_range`, `invalid_argument`; метод `what()`.
- **`throw;`** — пробросить принятое исключение выше (в `catch`).
- **`noexcept`** (C++11) — обещание не бросать; нарушили → `std::terminate`.
  Старые спецификации `throw(int)` из C++98 объявлены устаревшими и удалены.
- Исключения **дороги** (таблицы размотки, нет инлайнинга вокруг `try`), поэтому в
  «горячих» местах их не используют — там возвращают код ошибки.

> Задача после лекции: для трёх ситуаций — нехватка памяти, неверный аргумент,
> выход за границы — написать обработку `new`, `at()`, `dynamic_cast` и сравнить
> «код ошибки» против исключений.

## Короткая шпаргалка

| Тема | Главное |
|---|---|
| **`f(1, 2)` и `T&`** | левые ссылки **не** связываются с правыми значениями → нужен `T` или `const T&` |
| **`typename... Args`** | parameter pack — переменное число аргументов, типобезопасный аналог `...` из C |
| **`...`** | «повтори паттерн»: в объявлениях, в типах (`C<Tail>...`), при раскрытии (`f(t...)`) |
| **`sizeof...(t)`** | количество элементов пакета, известно на **компиляции** |
| **Рекурсия по пакету** | `Head` + `Tail...` → вызов с `t...`, обязателен **базовый случай** (пустой вызов) |
| **`tuple` / `pair`** | главное применение packs: `t.get<1>()` по индексу, `get<int>` по типу |
| **Функтор** | объект с `operator()` — вызывается как функция, имеет состояние |
| **Компаратор** | `cmp(a, b)` = сравнение; 3-й параметр `sort`; `std::less`/`std::greater` |
| **`std::less<T>`** | `struct less { bool operator()(const T&, const T&) const { return x < y; } };` |
| **Функтор vs функция** | есть поля + вызов **инлайнится** (тип — параметр шаблона) → быстрее указателя |
| **CRTP** | `struct Derived : Base<Derived>` — базовый класс знает тип потомка |
| **CRTP-вызов** | `static_cast<T*>(this)->f()` → `f` потомка **без `virtual`**, на этапе компиляции |
| **CRTP-цена** | нет vtable и vptr, вызов инлайнится; но объекты разного типа в один контейнер не сложить |
| **CRTP в std** | `std::enable_shared_from_this<T>` |
| **`new` без памяти** | бросает `std::bad_alloc`; `new (nothrow)` → `nullptr` |
| **`dynamic_cast<Derived&>(b)`** | провал → `throw std::bad_cast` (для ссылок); для указателей → `nullptr` |
| **`try`/`catch`** | `throw` прерывает выполнение → подъём по стеку → **первый подходящий** `catch` |
| **Исключение vs runtime error** | исключение — это то, что создано `throw`; выход за границы массива — **не** исключение |
| **UB** | **не ловится** ничем |
| **Порядок `catch`** | `throw int` при `catch (double)` первым → напечатается **только 2** |
| **Правило порядка** | частные → общие → `catch (...)` **последним** |
| **`catch (const std::exception& e)`** | ловим по `const`-ссылке, иначе срезка; `e.what()` — текст |
| **Stack unwinding** | локальные объекты уничтожаются → **RAII** спасает от утечек при `throw` |
| **`noexcept`** | обещание не бросать; бросил → `std::terminate` |
