# Лекция 10. Шаблоны (продолжение). Исключения — вопросы для практики

> Составлено по `final_readme.md`. Формулируй ответ сам, затем сверяйся с `<details>`.
> Вопросы с «что произойдёт»: сначала угадай (скомпилируется? что напечатается?), потом открывай.

---

## Исправления к прошлой лекции

### 1. ```cpp
template<class T, class Z> void f(T& x, Z& y);
```
Скомпилируется вызов `f(1, 2)`? Почему?

<details><summary>Ответ</summary>

**Нет.** `T&`/`Z&` — это **левые** ссылки, а `1` и `2` — **правые** (временные) значения,
с которыми левые ссылки не связываются. Лечится снятием «лишних» `&`.

</details>

### 2. Как исправить предыдущий случай, чтобы `f(1, 2)` работал и копирования не было?

<details><summary>Ответ</summary>

```cpp
template<class T, class Z>
void f(const T& x, const Z& y);
```

`const T&` принимает **всё**: lvalue, rvalue, `const` — самый универсальный параметр шаблона,
когда копировать жалко, а менять не надо.

</details>

## Variadic templates

### 3. Что означает многоточие `...` в шаблонном коде?

<details><summary>Ответ</summary>

**«Повтори паттерн»**. В `template<typename... Args>` повторяется `typename` → получаем список
типов. В `void f(Args... args)` повторяется `Args` → получаем список параметров, каждый своего
типа.

</details>

### 4. Запиши шаблон функции, принимающей произвольное количество аргументов произвольных типов.

<details><summary>Ответ</summary>

```cpp
template<typename... Args>
void f(Args... args);
```

Это **parameter pack** — типобезопасный аналог `...` из C (`printf`).

</details>

### 5. Напиши `print`, печатающий все аргументы, через пакет. Зачем базовый случай?

<details><summary>Ответ</summary>

```cpp
void print() {}                        // базовый случай

template<typename Head, typename... Tail>
void print(Head x, Tail... t) {
    std::cout << x;
    print(t...);
}
```

Рекурсия откусывает по одному аргументу. На последнем шаге пакет пуст → вызывается `print()`,
и под него **обязательно** должна существовать функция, иначе код не компилируется.

</details>

### 6. Как разворачивается вызов `print(1, 2.5, 'a')`? Назови `Head` и `Tail` на каждом шаге.

<details><summary>Ответ</summary>

```
print(1, 2.5, 'a')  →  Head = int,    Tail = {double, char}
print(2.5, 'a')     →  Head = double, Tail = {char}
print('a')          →  Head = char,   Tail = {}   (пусто)
print()             →  базовый случай
```

</details>

### 7. Как узнать количество аргументов в пакете? На каком этапе это известно?

<details><summary>Ответ</summary>

`sizeof...(t)` — это **константа**, известная **на этапе компиляции** (0, 1, 2, …).

```cpp
template<typename Head, typename... Tail>
void f(Head& x, Tail&... t) {
    std::cout << sizeof...(t);
    f(t...);
}
void f() {}
```

</details>

### 8. Что значит запись `C<Tail>...` в параметрах функции?

<details><summary>Ответ</summary>

Многоточие работает и в **типах**: паттерн `C<Tail>` повторяется для каждого элемента пакета →
`C<T1> t1, C<T2> t2, ...`. Тип `Tail` у всех аргументов свой.

</details>

### 9. Где применяются variadic templates? Назови два класса из лекции.

<details><summary>Ответ</summary>

`std::pair<T, U>` — упорядоченная пара; `std::tuple<T, U, V, ...>` — кортеж, т. е. набор
**произвольной длины** из разнотипных значений. Также на packs строятся `std::make_pair`,
`std::make_shared`, лямбды-обёртки и т. д.

</details>

### 10. Что такое `t.get<1>()` и `t.get<int>()` у кортежа?

<details><summary>Ответ</summary>

`get<1>()` — верни элемент **по номеру** (индекс известен на компиляции),
`get<int>()` / `std::get<int>(t)` — верни элемент **по типу**. Индекс и тип — не аргументы
функции, а **аргументы шаблона**, поэтому всё разрешается статически.

</details>

### 11. Как строится аналог `tuple` на пакетах (задание из лекции)?

<details><summary>Ответ</summary>

Рекурсия по пакету в **наследовании/вложенности**: `tuple<Head, Tail...>` хранит одно поле типа
`Head` + `tuple<Tail...>`; базовый случай — пустой кортеж. `get<I>()` спускается по цепочке,
сдвигая индекс. `get<T>()` — поиск по типу (нужна уникальность типов).

</details>

## Функторы

### 12. Что такое функтор?

<details><summary>Ответ</summary>

Объект, который можно **вызвать как функцию**: у него переопределён `operator()`.
Круглые скобки (в отличие от квадратных) **можно перегружать**.

</details>

### 13. Что такое компаратор?

<details><summary>Ответ</summary>

Объект, который поддерживает вызов себя **с двумя аргументами**, и этот вызов означает
**сравнение**: `cmp(a, b)`. Именно так устроена стандартная сортировка в STL — компаратор
третий параметр.

</details>

### 14. Запиши сигнатуру шаблонной `sort` с компаратором и покажи, как используется компаратор.

<details><summary>Ответ</summary>

```cpp
template<typename T, typename Cmp>
void sort(T* begin, T* end, Cmp cmp)   // begin, end — два указателя на массив
{
    ...
    cmp(*x, *y);   // может быть и функция, и объект
}
```

`cmp` — функтор; тип компаратора — **параметр шаблона**.

</details>

### 15. Реализуй `std::less<T>` (задание из лекции). Почему `struct`, а не `class`?

<details><summary>Ответ</summary>

```cpp
template<class T>
struct less {
    bool operator()(const T& x, const T& y) const {
        return x < y;
    }
};
```

`struct` — чтобы не писать `public` («а нам лень»). Для `greater<T>` — то же самое, только `x > y`.

</details>

### 16. Напиши свой компаратор, сортирующий `int` по модулю.

<details><summary>Ответ</summary>

```cpp
struct ByAbs {
    bool operator()(const int& x, const int& y) const {
        return std::abs(x) < std::abs(y);
    }
};

std::sort(v.begin(), v.end(), ByAbs());
```

</details>

### 17. Какое свойство обязан выполнять компаратор и что будет, если написать `<=`?

<details><summary>Ответ</summary>

**Строгое слабое упорядочение**: `cmp(a, a)` всегда `false`; `cmp(a, b)` и `cmp(b, a)` не могут
быть истинными одновременно. С «нестрогим» компаратором (`<=`) `std::sort` вылетает
(нарушение инварианта, выход за границы).

</details>

### 18. Чем функтор лучше указателя на функцию?

<details><summary>Ответ</summary>

1. **Состояние**: у функтора есть поля-настройки (`ByField{ key }`), у указателя на функцию — нет.
2. **Скорость**: тип компаратора — параметр шаблона → вызов **инлайнится**, нет непрямого вызова
   через указатель. Поэтому `std::sort` с лямбдой/функтором быстрее `qsort`.

</details>

## CRTP

### 19. Что такое CRTP? Запиши пример.

<details><summary>Ответ</summary>

**Curiously Recurring Template Pattern** — класс наследуется от шаблона, параметризованного **самим
собой**:

```cpp
template<class T>
struct Base {
    void f() { static_cast<T*>(this)->f(); }
};

struct Derived : public Base<Derived> {
    void f() {}
};
```

</details>

### 20. Что выведет/вызовет `Base<Derived>* b = &d; b->f();`? Какая из двух `f`?

<details><summary>Ответ</summary>

Вызовется **вторая** — `Derived::f()`. Внутри `Base<T>` тип `T` известен на этапе компиляции,
`this` кастуется к `Derived*` → вызывается `f` потомка. **Без `virtual`, без vtable.**

</details>

### 21. В чём смысл CRTP одной фразой?

<details><summary>Ответ</summary>

**Имитация виртуальных функций без слова `virtual`** — статический (шаблонный) полиморфизм:
связка «какая функция» происходит на этапе **компиляции**.

</details>

### 22. Сравни `virtual` и CRTP: этап решения, наценка, контейнер.

<details><summary>Ответ</summary>

| | `virtual` | CRTP |
|---|---|---|
| Когда решается «какая `f`» | на этапе **исполнения** (vtable) | на этапе **компиляции** |
| Наценка | vptr + непрямой вызов | нет, вызов инлайнится |
| Контейнер | `vector<unique_ptr<Base>>` | нельзя — все объекты **разного** типа |

</details>

### 23. Можно ли написать `Base* b = &d;` в примере с CRTP?

<details><summary>Ответ</summary>

**Нельзя.** `Base` сама по себе **не** является базой `Derived`: база — конкретная инстансация
`Base<Derived>`. Правильно: `Base<Derived>* b = &d;`.

</details>

### 24. Какие требования накладывает CRTP и какая типичная ошибка в нём возможна?

<details><summary>Ответ</summary>

- `T` обязан быть унаследован от `Base<T>` **и сам** определять `f()`, иначе
  `static_cast<T*>(this)->f()` — ошибка компиляции;
- если `f` в `Derived` скрыта/отсутствует, `Base::f → Derived::f → Base::f` уходит в
  **бесконечную рекурсию**.

</details>

### 25. Где применяется CRTP? Назови готовый пример из стандартной библиотеки.

<details><summary>Ответ</summary>

Счётчики объектов класса; подмешивание операторов (`+=`, `++`, арифметика) в класс;
интерфейсы без виртуальных вызовов; fluent API.
В std: **`std::enable_shared_from_this<T>`**.

</details>

## Исключения: мотивировка

### 26. `int* p = new int[1000];` — взяли слишком много памяти, ОС дать не может. Что происходит?

<details><summary>Ответ</summary>

Обычный `new` **бросает исключение** `std::bad_alloc` — выполнение прерывается, и код, который
не проверял указатель, всё равно корректно «сломается».
`nullptr` — лишь частичное решение (и то только для формы `new (std::nothrow) int[1000]`, где
приходится проверять вручную).

</details>

### 27. Что делает `dynamic_cast<Derived&>(b)`, если `b` на самом деле `Base`?

<details><summary>Ответ</summary>

Бросает **`std::bad_cast`**. Для **указателей** провал даёт `nullptr` (нужна проверка), а для
**ссылок** выдать нечего — поэтому `throw`. Отсюда и мотивация: механизму, который умеет
прервать выполнение и передать сигнал «я не могу» наверх, нужна языковая поддержка.

</details>

## `throw` / `try` / `catch`

### 28. Опиши последовательность: что происходит после `throw` внутри `try`?

<details><summary>Ответ</summary>

1. выполняем код внутри `try`;
2. кто-то делает `throw` → текущее выполнение **прерывается**;
3. поднимаемся вверх по стеку вызовов в поисках **подходящего** `catch`;
4. выполняется тело **первого подходящего** `catch`, дальше по списку не смотрим.

</details>

### 29. Как правильно ловить «общее» исключение стандартной библиотеки и почему по ссылке?

<details><summary>Ответ</summary>

```cpp
catch (const std::exception& e) { std::cout << e.what(); }
```

По **`const`-ссылке**: по значению (`catch (std::exception e)`) произошла бы **срезка** —
потомок (`out_of_range`) превратился бы в базу, и `what()` стал бы общим текстом.

</details>

### 30. Что можно бросить (`throw`) и как правильно это делать?

<details><summary>Ответ</summary>

Бросить можно **что угодно** — даже `int` или `char*`, и бросают **по значению**
(`throw MyError(...)`), чтобы не указывать на локальный объект, который умрёт при размотке стека.
Ловить — по `const`-ссылке.

</details>

## Исключения vs runtime error

### 31. «Каждое исключение — это runtime error». Верно?

<details><summary>Ответ</summary>

**Нет.** Не каждое исключение — runtime error, и не каждый runtime error — исключение.
**Исключение** — это то, что создаётся `throw` (явным в моём коде или неявным в библиотеке:
`new` → `bad_alloc`, `at()` → `out_of_range`, `stoi` → `invalid_argument`). Есть и исключения,
возникающие вне «ошибки времени выполнения» (например, сигнальные/структурные ситуации).

</details>

### 32. ```cpp
int a[100];
std::cout << a[1000];
```
Поймает ли это `catch(...)`?

<details><summary>Ответ</summary>

**Нет.** Это **не** исключение, а **runtime error / UB**: ничего не бросается, ловить нечего.
**UB — НЕ ПОЙМАТЬ**: ни `catch`, ни что-либо ещё не спасает от выхода за границы массива,
мусорного указателя, гонки данных. Исключения — про **ожидаемые и объявленные** ситуации.

</details>

### 33. Как сделать ту же ситуацию ловимой?

<details><summary>Ответ</summary>

Использовать доступ с проверкой: `v.at(1000)` у `std::vector` бросает `std::out_of_range`,
который ловится. То есть «ловимость» — свойство API, а не языка вообще.

</details>

## Порядок обработки (вопрос на собеседовании)

### 34. ```cpp
try { ... }
catch (double d) { std::cout << 2; }
catch (int x)    { std::cout << 3; }
catch (...) {}
```
Бросил `int`. Напечатается `2` или `3`?

<details><summary>Ответ</summary>

Напечатается **только `2`**. Выбор идёт по **первому подходящему** `catch`, а `int` → `double` —
допустимое неявное преобразование, первая ветка подходит. Ветка `catch (int)` не выполняется
**вообще**, до неё не доходит.

</details>

### 35. Сформулируй правило порядка блоков `catch`.

<details><summary>Ответ</summary>

От **частных** типов к **общим**: сначала потомки (`bad_alloc`), затем база (`std::exception`),
`catch (...)` — **последним**. Иначе всё, что стоит после подходящего раньше, мертво
(а `catch (const std::exception&)` до `catch (const std::runtime_error&)` — типичная ошибка).

</details>

### 36. Что напечатает код из №34, если бросить `std::runtime_error`?

<details><summary>Ответ</summary>

**Ничего из `2`/`3`** — `std::runtime_error` не преобразуется ни в `double`, ни в `int`,
поэтому подходит только `catch (...)` (пустой). Если бы `catch (...)` не было — программа
завершилась бы (`std::terminate`).

</details>

## За границами лекции

### 37. Что происходит с локальными объектами на пути от `throw` до `catch`? Почему важен RAII?

<details><summary>Ответ</summary>

**Stack unwinding** — при подъёме к `catch` уничтожаются **все** локальные объекты на пути
(вызываются их деструкторы). Поэтому ресурсы держим в объектах, чьи деструкторы их освобождают
(**RAII**) — тогда при `throw` утечки нет. «Сырой» `new`/`malloc` без обёртки — гарантия утечки.

</details>

### 38. Перечисли известную иерархию исключений из `<stdexcept>`.

<details><summary>Ответ</summary>

База — **`std::exception`** (метод `what()`). От неё: `logic_error` → `invalid_argument`,
`out_of_range`, `domain_error`; `runtime_error`; отдельно — `bad_alloc`, `bad_cast` (из `<new>`,
`<typeinfo>`).

</details>

### 39. Как пробросить принятое исключение выше и что такое `noexcept`?

<details><summary>Ответ</summary>

`throw;` (без объекта) внутри `catch` — пробросить то же исключение наверх.
`noexcept` (C++11) — обещание не бросать; если бросили — `std::terminate`. Старые спецификации
`throw(int)` из C++98 устарели и удалены.

</details>

### 40. Почему в «горячих» местах и в системном коде исключения часто не используют?

<details><summary>Ответ</summary>

Они **дороги**: таблицы размотки, отключение части оптимизаций/инлайнинга вокруг `try`,
непредсказуемая стоимость проброса через много кадров. Поэтому там возвращают код ошибки.
Компромисс: исключения — для **редких** нештатных ситуаций, не для управления потоком.

</details>

## Итоговый вопрос

### 41. Объясни «в одну строку» на собеседовании: чем функтор отличается от функции, чем CRTP отличается от `virtual`, и чем исключение отличается от UB?

<details><summary>Ответ</summary>

**Функтор** — объект с `operator()`: в отличие от функции имеет состояние, а его тип — параметр
шаблона, поэтому вызов инлайнится (быстрее указателя на функцию).
**CRTP** — `struct Derived : Base<Derived>`: базовый класс знает тип потомка и вызывает его метод
через `static_cast<T*>(this)->f()`, то есть **статический** полиморфизм на этапе **компиляции**
без vtable, тогда как `virtual` решает «какая функция» в рантайме.
**Исключение** — это то, что явно создано `throw` и ловится `catch` (первым подходящим);
**UB** (выход за границы, мусорный указатель) ничего не бросает и **не ловится** — от него спасает
только корректный код и RAII на пути размотки стека.

</details>
