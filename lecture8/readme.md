7) Виртуальные функции
Очень важно на собесах и чем он отличается от невиртуальных
Это одно из проявлений полиморфизма

struct Base {
    void f()
}

struct Derived: Base {
    void f()
}

D d;
B& b = d;
b.f(); // вызовется f которая в Base

Пример: у меня есть указатели/ссылки на некоторый объекты, после этого я
пробегаюсь по нему и для каждого из этих объектов что-то спрашиваю, например площадь,
но бывают разные фигуры, и логично, что он бы не как параллелограм начинал себя вести,
а как то, чем он на самом деле является.

Полиморфизм: одна и та же функция в применении к разным сущностям дает разный результат

Еще пример: сварить гречку, сварить макараны, сварить рис, слово сварить в каждом случае
означает разные действия


struct Base {
    virtual void f()
}

struct Derived: Base {
    void f()
}

Виртуальная функция - это такая функция, что если вы вызываете ее у объекта, компилятор 
проверяет, а как на самом деле у того, у чего вы ее вызвали и в зависимости этого вызывает 
правильную версию

итого 

struct Base {
    virtual void f()
}

struct Derived: Base {
    void f()
}

тогда 
D d;
B& b = d;
b.f(); // вызовется f которая в Derived

и эта штука позволяет осуществить полиморфизм

Пример 

struct Base {
    virtual void f();
    int a;
}

struct Derived: Base {
    void f();
    int b;
}

D* d = new D();
B* b = d;
delete b;

Вопрос: Скомпилируется ли код? Упадет? Если не упадет, все ли будет хорошо?

Скомпилируется, но будет утечка памяти:
Проблема тут delete b компилятор полез в деструктор b, увидел, что он не виртуальный 
и удалил так, как будто это на самом деле объект типа B, тоесть D не удалилась

Прикол: у предыдущих потоков было задание на иерархию геометрических классов Rectangle,
Parallelogram, Rhombus, Square и прогонялась по 100000 раз часть:
D* d = new D();
B* b = d;
delete b;

и у людей падало из-за memory limit

Поэтому, если вы пишете класс и собираетесь обращаться к нему через указатель на базовый
класс, то должен быть виртуальный деструктор

Нужно было написать 
virtual ~B(){}

9) Абстрактные классы
Представьте, что у нас геометрические фигуры  Rectangle, Parallelogram, Rhombus, Square
и у каджой есть метод нахождения площади и я хочу создать массив из фигур не уточняя
какие это фигуры, тогда можно написать 

virtual double area() const = 0;
функция, которая не подразумевает реализацию, тогда я не смогу создавать объект такого типа

Такие классы, в которых есть чисто (pure) виртуальные функции называются абстрактными и 
абстрактные классы запрещают создавать объекты своих типов

Классы, в которых есть виртуальные функции называются полиморфные

class Shape {
    public: virtual double area() const = 0; // общее название, сам он не знает, как
    // реализовать area для любой фигуры

};
+ нужен виртуальный деструктор

и area должны определять все, кто наследует shape        

Если я наследую абстрактный класс и не определяю чисто виртуальную функцию, то я сам
становлюсь абстрактным классом и меня нельзя переопределить

пусть и забыл const перед = 0, чтобы было тогда?
class Shape {
    public: virtual double area() = 0; // общее название, сам он не знает, как
    // реализовать area для любой фигуры

};
const часть сигнатуры

Если забуду написать const перед = 0 то получится, что я не переопределил метод предка,
а написал собственный метод, который будет работать по общим правилам перегрузки, 
в C++ застраховали от таких проблем словом override
