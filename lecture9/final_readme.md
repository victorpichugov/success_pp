## 1. Мотивировка: зачем нужны шаблоны

После наследования в арсенале осталось не так много — а шаблоны пригодятся по любому. Даже `vector<int>` — это **шаблон**.

Классический пример: `swap`.

```cpp
void swap(int& x, int& y) {
    int t = x;
    x = y;
    y = t;
}
```

Я хочу и `swap(double, double)`, и `swap(bool, bool)`… Неужели надо каждый раз копировать функцию?

> Хочется объявлять вещи **универсальными для любых типов**. Для этого и существует `template`
> (аналог `generic` в Java) — средство, которое позволяет писать **обобщённо**.

---

## 2. Объявление шаблонов

Шаблоны бывают **у функций** и **у классов**. Общий вид объявления:

```cpp
template<список параметров шаблона>
```

### 2а. Шаблон функции

```cpp
template<typename T>
void swap(T& x, T& y) {
    T t = x;
    x = y;
    y = t;
}
```

`typename` можно написать и как `class`:

```cpp
template<class T>
void swap(T& x, T& y) { /* ... */ }
```

В `main`:

```cpp
int x = 3, y = 2;
swap(x, y);        // T = int — аргумент **выведен** автоматически
swap<int>(x, y);   // можно указать тип явным образом
```

### 2б. Шаблон класса

Класс, параметризованный типом `T`:

```cpp
template<typename T>
class C {
    /* ... */
};

int main() {
    C<int> c;   // инстанциация: создаём класс C, где T заменён на int
}
```

Для **функций** аргумент шаблона можно не указывать — компилятор **выведет** (deduce) его из аргументов вызова. Для **классов** аргумент указывать **обязательно** — выводить не из чего.

## 3. Шаблоны и полиморфизм

**Шаблоны — это ещё одно проявление полиморфизма.** Ключевое отличие от виртуальных функций — **этап** работы:

- **виртуальные функции** — как именно поведётся объект, определяется **на этапе исполнения** (после компиляции, через vtable);
- **шаблоны** — «как поведутся» все версии определяются **на этапе компиляции** (для каждого типа компилятор генерирует свой код).

### 3а. Вопрос для собеседований: «Что такое полиморфизм в C++?»

Ответ — три проявления:

1. **перегрузка функций**;
2. **шаблоны**;
3. **виртуальные функции**.

А тогда что наследование и инкапсуляция? Это **отдельные** понятия ООП, а не полиморфизм:

- **наследование** — «являюсь частным случаем», переиспользование кода (тема 7–8 лекций);
- **инкапсуляция** — скрываем данные и выставляем наружу только нужные методы (`private`/`public`).

Полиморфизм — про «одна и та же операция — разное поведение в зависимости от объекта/типа»; наследование и инкапсуляция — про **структуру** кода.

## 4. Специализация шаблонов

Можно объявить шаблон **общего** вида, а затем написать **частный** вариант для конкретного набора типов.

### 4а. Полная специализация

```cpp
template<class T>
void f(T& x);

template<>          // пустые <> = «полная» специализация, без параметров
void f(int x);
```

```cpp
f(1);   // вызовётся специализация f(int)
```

> Синтаксис обязателен: `template<>` перед объявлением. Просто `void f(int x);` **без** `template<>` — это уже обычная **перегрузка**, а не специализация (в перегрузочном разрешении обычная функция вообще получает приоритет над шаблоном).

### 4б. Специализация с несколькими параметрами

```cpp
template<class T, class Z>
void f(T& x, Z& z);          // «первичный» шаблон

template<>
void f(int x, int y);        // полная специализация: оба параметра подставлены

template<class T>
void f(int x, T& y);         // ЧАСТИЧНАЯ специализация: T всё ещё параметр
```

```cpp
f(5, 0.5);   // вызовётся частичная специализация: T = double
```

Разница видна на синтаксисе: в `template<>` ничего не пишется (все аргументы подставлены), а в `template<class T>` — **один** аргумент остался параметром.

### 4в. Правила выбора версии

1. Шаблон **всегда старается подобрать точное соответствие**;
2. Из всех **подходящих** версий компилятор выбирает **наиболее специализированную**.

## 5. `typedef` — новое имя для типа

В C++ можно ввести **новое название** для типа:

```cpp
typedef (что) (как назвать);
typedef verylongtypename<int, vector<int>> mytype;
```

Ограничение: все аргументы фиксируются **в момент объявления** — `mytype<int>` написать нельзя.

### 5а. Шаблонный псевдоним (`using`, C++11)

Пусть:

```cpp
typedef verylongtypename<int, vector<T>> mytype;   // хочется, чтобы T было параметром
```

и хочется писать `mytype<T>` — для этого есть **шаблонный typedef** (алюас):

```cpp
template<typename T>
using mytype = verylongtypename<int, vector<T>>;

// теперь:
mytype<int> a;
mytype<double> b;   // разные типы!
```

Современный стиль — всегда `using` вместо `typedef` (синтаксис одинаковый для не-шаблонов и шаблонов).

## 6. `typename` — вложенные типы шаблонов

Пусть есть шаблонный класс, внутри которого «запоминается» тип:

```cpp
template<class T>
class C {
    typedef T type;
};
```

Ситуация: есть итератор по контейнеру, и **неизвестно** (не через `auto`), что за тип. Как объявить переменную такого типа?

```cpp
int main() {
    C<T>::type x;          // ОШИБКА КОМПИЛЯЦИИ!
    typename C<T>::type x; // OK
}
```

> `typename` — ключевое слово, которое говорит компилятору: «вот это **тип**, а не статическое поле/значение». Без него `C<T>::type` не может быть однозначно разобран (имя `type` могло бы указывать и на значение), поэтому код не компилируется.

Встречается повсюду, где берётся вложенный тип шаблонного типа: `typename std::vector<T>::iterator` и т. п.

## 7. Тип-трейты: `remove_const`, `remove_reference` и др.

Средства для **манипуляции типами на этапе компиляции**: «такой же как `T`, только без `const`», «такой же как `T`, только без ссылки» — это всё **должно разрешаться на этапе компиляции**.

### 7а. Как устроен `remove_const`

```cpp
template<class T>
struct remove_const<const T> {   // ЧАСТИЧНАЯ специализация: ловим const
    typedef T type;              // «без const»
};

template<class T>
struct remove_const<T> {         // первичный шаблон: не const — оставляем как есть
    typedef T type;
};

// использование:
typename remove_const<T>::type x;
```

Как это читается: первичный шаблон подходит **для любого** `T`; при `T = const int` компилятор выбирает **наиболее специализированную** версию (по правилу из §4в) — первую, — и её `type` — `int` (без `const`).

### 7б. Как устроен `remove_reference`

```cpp
template<class T>
struct remove_reference<T&> {    // специализация: ловим левые ссылки
    typedef T type;
};

template<class T>
struct remove_reference<T> {     // первичный: ссылка не была — как есть
    typedef T type;
};
```

### 7в. Комбинации

```cpp
void f(T& t) {
    // переменная такого же типа, как T, но без const и без ссылки:
    typename remove_reference<typename remove_const<T>::type>::type x;
}
```

В стандартной библиотеке уже есть готовые: `std::remove_const`, `std::remove_reference`, `std::add_pointer`, `std::is_same` и т. д. (заголовки `<type_traits>`).

> **Обязательно понять эту схему**: первичный шаблон + специализация «ловит конкретный вид типа» + `type`-член + `typename` при обращении. На этом строится почти вся магия шаблонного кода в std.

## 8. Вывод аргументов шаблона и ссылки

### 8а. `void f(T& x)` — что выведет компилятор?

```cpp
template<class T>
void f(T& x) {}
```

```cpp
int main() {
    int x; f(x);                 // T = int,        параметр — int&
    int& y = x; f(y);            // T = int,        параметр — int&
    const int z = 0; f(z);       // T = const int,  параметр — const int&
    const int& t = z; f(t);      // T = const int,  параметр — const int&
}
```

Два вопроса: сохранится ли `&`? Сохранится ли `const`?

> **Ответ: `&` игнорируется, `const` сохраняется.**
> Ссылка «разворачивается» в выводимый `T`, а `const` в него **входит** — иначе запись `x = 5;` через `const int&` позволила бы менять константу, и это было бы ошибкой.

### 8б. `void f(T x)` — передача по значению

```cpp
template<class T>
void f(T x) {}
```

```cpp
int main() {
    int x; f(x);                 // T = int
    int& y = x; f(y);            // T = int
    const int z = 0; f(z);       // T = int
    const int& t = z; f(t);      // T = int
}
```

Теперь **и `const`, и ссылки отбрасываются**: параметр — копия, его «состояние» (ссылочность, константность) для `T` не важно.

### 8в. Заметка про «универсальные ссылки»

В лекции эта ситуация называется **универсальными ссылками**. Важно не путать с C++11-конструкцией: **истинная универсальная (rvalue) ссылка** возникает только при выводе в параметр **`T&&`**; её поведение с lvalue/rvalue — отдельная (следующая) тема. Здесь ключевое: для `T&` — `&` отбрасывается, `const` сохраняется; для `T` (по значению) — отбрасывается всё.

## 9. Не-типизованные параметры шаблона (non-type template parameters)

Параметр шаблона **не обязан быть типом** — это может быть **значение**:

```cpp
// хочу создать массив константного размера
template<typename T, int n>
class array {
    /* ... */
};
```

```cpp
array<int, 10> a;
array<int, 100> b;   // array<int, 10> и array<int, 100> — РАЗНЫЕ типы!!
```

Вывод non-type-параметра работает так же, как вывод типа (из аргумента вызова), если значение можно вычислить на этапе компиляции.

В non-type-параметрах можно использовать и **указатели** (и указатели на функции):

```cpp
template<typename T, T* p>   // попробовать!
```

(в старых C++ — только `static const`/`extern`-ссылки, в C++11+ — сами указатели).

### 9а. Параметры шаблона, которые сами являются шаблонами

```cpp
template<typename X, template<typename> class T>
void f(const T<X>& t) {
    /* ... */
}
```

Здесь `T` — **сам шаблон** (`vector`, `deque`, `list`…), `X` — его параметр. Вызовы:

```cpp
f(std::vector<int>());    // T = vector, X = int
f(std::deque<double>());  // T = deque, X = double
```

### 9б. Итог: три вида параметров шаблона

1. **типы** (`typename`/`class`);
2. **non-type**: константные значения (`int`, указатели, …);
3. **шаблоны** (`template<typename> class T`).

---

## 10. Значения по умолчанию и переменное число параметров

Шаблоны допускают **значения по умолчанию**:

```cpp
template<typename T, int n = 10>   // n можно не указывать
class array {};
```

А переменное **количество** аргументов шаблона задаётся **елотным** (pack):

```cpp
template<typename... Ts>
```

Вот так и надо делать переменное количество аргументов (variadic templates) — на них строится `std::tuple`, `std::make_pair` и многое другое.

## Короткая шпаргалка

| Тема | Главное |
|---|---|
| **Мотивация** | Не дублировать `swap(int&…)`, `swap(double&…)` — один `template`-код на все типы |
| **Синтаксис** | `template<...>`; `typename T` ≡ `class T` |
| **Вызов** | `f(x)` — аргумент выводится; `f<int>(x)` — явно (для классов — всегда явно) |
| **Полиморфизм** | Три вида: перегрузка, **шаблоны** (компиляция), **virtual** (рантайм) |
| **Специализация** | `template<>` — полная; `template<class T>` — частичная |
| **Правила выбора** | 1) точное соответствие; 2) из подходящих — самая специализованная |
| **`typedef` / `using`** | Новое имя для типа; `using` в C++11 + **шаблонные** псевдонимы `mytype<T>` |
| **`typename`** | «это **тип**»: `typename C<T>::type x;` — без `typename` — ошибка компиляции |
| **Тип-трейты** | `remove_const`/`remove_reference`: первичный шаблон + частичная специализация + `type` |
| **Вывод `T&`** | `&` **отбрасывается**, `const` **сохраняется** |
| **Вывод `T` (по значению)** | `const` и `&` **отбрасываются** |
| **Non-type** | `int n`, указатели `T* p`; `array<int,10>` и `array<int,100>` — **разные типы** |
| **Шаблоны-параметры** | `template<typename> class T` — T сам шаблон (`vector`, `deque`…) |
| **3 вида параметров** | типы, константные значения, шаблоны |
| **`...`** | Переменное число аргументов (parameter pack), значения по умолчанию — тоже можно |
