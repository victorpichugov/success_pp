# Лекция 9. Шаблоны — вопросы для практики

> Составлено по `final_readme.md`. Формулируй ответ сам, затем сверяйся с `<details>`.
> Вопросы с «что произойдёт»: сначала угадай (скомпилируется? какой тип?), потом открывай.

---

## Базовая мотивация и объявления

### 1. Почему вообще нужны шаблоны? Каков классический пример из лекции?

<details><summary>Ответ</summary>

Чтобы не дублировать одинаковый код для разных типов: написал `swap(int&, int&)` — а хочется
`swap(double, double)` и `swap(bool, bool)`. `template` (аналог `generic` в Java) позволяет
писать **универсально для всех типов**. Даже `vector<int>` — это шаблон.

</details>

### 2. Запиши объявление шаблона функции `swap` и шаблона класса `C<T>`. Чем `typename` и `class` в `template<...>` отличаются?

<details><summary>Ответ</summary>

```cpp
template<typename T>
void swap(T& x, T& y) { T t = x; x = y; y = t; }

template<typename T>
class C { /* ... */ };
```

Ничем — `class` здесь можно заменить на `typename` (в `template<...>` они синонимы).

</details>

### 3. `swap(x, y);` и `swap<int>(x, y);` — в чём разница? А можно ли так написать для класса?

<details><summary>Ответ</summary>

В первом аргумент **выведен** (deduce) компилятором из аргументов вызова, во втором — указан
явно. Для **классов** явная запись `C<int> c;` **обязательна**: выводить аргумент не из чего.

</details>

## Полиморфизм

### 4. Что такое полиморфизм в C++? Перечисли все проявления, которые дают на собеседовании.

<details><summary>Ответ</summary>

Три проявления:

1. **перегрузка функций**;
2. **шаблоны**;
3. **виртуальные функции**.

</details>

### 5. На каком этапе работают шаблоны, а на каком — виртуальные функции?

<details><summary>Ответ</summary>

**Шаблоны — на этапе компиляции** (для каждого типа генерируется свой код).
**Виртуальные функции — на этапе исполнения** (после компиляции, через vtable), там уже
определяется, как именно поведётся объект.

</details>

### 6. А наследование и инкапсуляция — это тоже полиморфизм? Чем они отличаются?

<details><summary>Ответ</summary>

Нет, это **отдельные** понятия ООП. **Наследование** — «являюсь частным случаем»,
переиспользование кода. **Инкапсуляция** — скрываем данные, наружу — только нужные методы.
Полиморфизм — про «одна и та же операция — разное поведение в зависимости от объекта/типа».

</details>

## Специализация

### 7. Что такое специализация шаблона? Чем `template<>` отличается от `template<class T>`?

<details><summary>Ответ</summary>

Специализация — **частный** вариант шаблона для конкретного набора типов.

- `template<>` — **полная** специализация: все параметры подставлены, ничего не осталось;
- `template<class T>` — **частичная**: `T` остался параметром, остальные подставлены.

</details>

### 8. ```cpp
template<class T> void f(T& x);
template<> void f(int x);
```
Что вызовет `f(1)` и почему?

<details><summary>Ответ</summary>

Специализацию `f(int)`: шаблон сначала ищет **точное соответствие**, а из всех подходящих
выбирает **наиболее специализированную** версию.

</details>

### 9. ```cpp
template<class T, class Z> void f(T& x, Z& z);
template<> void f(int x, int y);
template<class T> void f(int x, T& y);
```
Какая версия вызовется для `f(5, 0.5)`?

<details><summary>Ответ</summary>

**Частичная** специализация `template<class T> void f(int, T&)`: `int` совпадает точно,
`T = double` выводится. Полная `f(int, int)` не подходит — второй аргумент не `int`.

</details>

### 10. Если написать просто `void f(int x);` (без `template<>`) рядом с `template<class T> void f(T& x);` — это специализация?

<details><summary>Ответ</summary>

**Нет**, это обычная **перегрузка**. В перегрузочном разрешении нешаблонная функция получает
приоритет над шаблоном. Специализацией она становится только с явным `template<>` перед ней.

</details>

## `typedef` / `using` / `typename`

### 11. Зачем нужен `typedef`? Запиши пример.

<details><summary>Ответ</summary>

Ввести **новое название** для (возможно, очень длинного) типа:

```cpp
typedef verylongtypename<int, vector<int>> mytype;
```

Ограничение: аргументы фиксируются в момент объявления — `mytype<int>` так написать нельзя.

</details>

### 12. Хочется, чтобы `mytype<T>` зависел от `T`. Как сделать (C++11)?

<details><summary>Ответ</summary>

**Шаблонным псевдонимом** `using`:

```cpp
template<typename T>
using mytype = verylongtypename<int, vector<T>>;

mytype<int> a;
mytype<double> b;   // разные типы
```

Современный стиль — всегда `using`, а не `typedef`.

</details>

### 13. ```cpp
template<class T> class C { typedef T type; };
```
`C<T>::type x;` — скомпилируется? Как исправить?

<details><summary>Ответ</summary>

**Ошибка компиляции.** Имя `type` в шаблонном контексте неоднозначно (могло бы быть и значением),
поэтому его нужно пометить словом **`typename`**:

```cpp
typename C<T>::type x;   // OK
```

`typename` говорит компилятору: «вот это **тип**».

</details>

## Тип-трейты

### 14. Как устроен `std::remove_const` (первичный шаблон + специализация)? Объясни, как он «ловит» `const`.

<details><summary>Ответ</summary>

```cpp
template<class T>
struct remove_const<const T> { typedef T type; };  // частичная: ловим const
template<class T>
struct remove_const<T>       { typedef T type; };  // первичный: как есть
```

При `T = const int` компилятор выбирает **наиболее специализированную** версию (первую),
и её `type` — `int` без `const`. Для не-`const` срабатывает первичный.

</details>

### 15. Как устроен `remove_reference`? Какие два шаблона в нём есть?

<details><summary>Ответ</summary>

```cpp
template<class T> struct remove_reference<T&> { typedef T type; };  // ловим ссылки
template<class T> struct remove_reference<T>  { typedef T type; };  // не ссылка — как есть
```

Схема та же: специализация «ловит» конкретный вид типа (ссылку), первичный — всё остальное.

</details>

### 16. Что значит «всё это разрешается на этапе компиляции» в контексте `typename remove_const<T>::type`?

<details><summary>Ответ</summary>

Манипуляции типом (снять `const`/ссылку) происходят **до** исполнения — на этапе
**компиляции**, когда компилятор подставлял реальный тип в `T`. Никакого рантайм-кода:
результат — просто другой тип, записанный в `type`.

</details>

### 17. Как записать тип «такой же как `T`, только без `const` и без ссылки» (комбинация трейтов)?

<details><summary>Ответ</summary>

```cpp
typename remove_reference<typename remove_const<T>::type>::type
```

В std готовы: `std::remove_const`, `std::remove_reference`, `std::add_pointer`, `std::is_same`
(заголовки `<type_traits>`).

</details>

## Вывод аргументов и ссылки

### 18. ```cpp
template<class T> void f(T& x) {}
```
Что выведёт компилятор `T` для: `int x; f(x);`? `const int z; f(z);`?

<details><summary>Ответ</summary>

- `int x; f(x);` → `T = int`, параметр — `int&`.
- `const int z; f(z);` → `T = const int`, параметр — `const int&`.

</details>

### 19. Сформулируй правило вывода для `T&`: сохранится ли `&`? Сохранится ли `const`?

<details><summary>Ответ</summary>

**`&` игнорируется, `const` сохраняется.** Ссылка «разворачивается» в `T`, а `const` в него
**входит** — иначе через `const int&` можно было бы менять константу.

</details>

### 20. А для `void f(T x)` (по значению) — что с `const` и `&`?

<details><summary>Ответ</summary>

**И `const`, и ссылки отбрасываются**: параметр — копия, его ссылочность/константность для
вывода `T` не важны. `int x; const int z; f(x); f(z);` — везде `T = int`.

</details>

### 21. Чем ситуация из лекции («универсальные ссылки» для `T&`) отличается от C++11 rvalue-ссылок `T&&`?

<details><summary>Ответ</summary>

В лекции «универсальными» называются параметры `T&` — и там правило: `&` отбрасывается,
`const` сохраняется. **Истинная** универсальная (rvalue) ссылка — это отдельная C++11-конструкция
с параметром **`T&&`**, чьё поведение с lvalue/rvalue — следующая тема. Не путать.

</details>

## Non-type параметры и шаблоны-параметры

### 22. Что такое non-type template parameters? Приведи пример из лекции.

<details><summary>Ответ</summary>

Параметр шаблона, **не являющийся типом**, а **значением** (константой):

```cpp
template<typename T, int n>
class array { /* ... */ };

array<int, 10> a;
array<int, 100> b;   // array<int,10> и array<int,100> — РАЗНЫЕ типы
```

Выводится из аргумента, если значение известно на этапе компиляции.

</details>

### 23. Какие ещё non-type параметры допустимы?

<details><summary>Ответ</summary>

**Указатели** (и на функции):

```cpp
template<typename T, T* p>   // попробовать!
```

(в старых C++ — `static const`/`extern`-ссылки, в C++11+ — сами указатели).

</details>

### 24. ```cpp
template<typename X, template<typename> class T>
void f(const T<X>& t) {}
```
Что здесь `T` и что — `X`? Приведи два вызова.

<details><summary>Ответ</summary>

`T` — **сам шаблон** (`vector`, `deque`…), `X` — его параметр-тип. Вызовы:

```cpp
f(std::vector<int>());    // T = vector, X = int
f(std::deque<double>());  // T = deque,  X = double
```

</details>

### 25. Перечисли три вида параметров шаблона.

<details><summary>Ответ</summary>

1. **типы** (`typename`/`class`);
2. **non-type**: константные значения (`int`, указатели…);
3. **шаблоны** (`template<typename> class T`).

</details>

## Значения по умолчанию и packs

### 26. Допускают ли шаблоны значения по умолчанию? Запиши пример.

<details><summary>Ответ</summary>

Да:

```cpp
template<typename T, int n = 10>
class array {};   // n можно не указывать
```

</details>

### 27. Как записать шаблон с **переменным** числом аргументов? Где это применяется?

<details><summary>Ответ</summary>

С параметр-пак (parameter pack) — многоточие:

```cpp
template<typename... Ts>
```

На этом строится `std::tuple`, `std::make_pair` и многое другое (variadic templates).

</details>

## Итоговый вопрос

### 28. Объясни «в одну строку» на собеседовании: что такое шаблон, в чём он отличается от перегрузки и от виртуальной функции, и на каком этапе всё это работает?

<details><summary>Ответ</summary>

**Шаблон** — средство писать один обобщённый код для **любых типов** (компилятор генерирует
версию под каждый реальный тип). От **перегрузки** — в переписании кода вручную под каждый
тип; от **виртуальной функции** — этапе: шаблоны работают на этапе **компиляции** (статически),
виртуальные — на **выполнении** (динамически, через vtable). Вместе с перегрузкой и `virtual`
это три проявления полиморфизма в C++.

</details>
