## Часть 1. Перегрузка операторов

### 1.1. Оператор как функция

В C++ любой оператор — это функция со специальным именем. Оператор можно реализовать:

- **внутри класса** (member-функция) — тогда левым операндом неявно выступает `this`;
- **вне класса** (free-функция, часто `friend`) — оба операнда передаются обычными аргументами.

`const` после `)` в объявлении метода — позволяет вызывать метод из **константного** объекта (обещание не менять состояние).

Классический приём: реализовать `+` через `+=`, чтобы не дублировать логику:

```cpp
C& C::operator+=(const C& x) {
    // ... аккумулируем x в *this
    return *this;
}

C C::operator+(const C& x) const {
    C sum = *this;   // копия
    sum += x;        // переиспользуем +=
    return sum;      // возвращаем по значению
}
```

### 1.2. Когда оператор обязан быть вне класса

У member-оператора левый операнд — всегда `this`. Поэтому:

| Выражение | Member-функция | Комментарий |
|---|---|---|
| `c + 5` | ✅ | читается как `this + 5` |
| `5 + c` | ❌ | `this` оказался бы левым операндом — `5`, а это невозможно |

Решение: вынести оператор **за класс** как свободную функцию — тогда работают оба варианта:

```cpp
C operator+(const C& x, const C& y) {
    // ...
}
```

Чего сделать **нельзя**:

- `5 += c;` — невозможно: левый операнд сложного присваивания должен быть изменяемым значением, у `int` такого механизма нет;
- `c += 5;` — возможно (member-функция);
- `5 = c;` — невозможно: левая часть `=` должна быть lvalue, а `5` — константа.

### 1.3. Проблема: `c1 + c2 = 5` — присваивание в rvalue

```cpp
C c1 = 3;
C c2 = 4;
c1 + c2 = 5;   // для наших классов — КОМПилируется!
```

Для встроенных типов `3 + 4 = 5` — ошибка: левый операнд `=` обязан быть **lvalue**, а `3 + 4` — rvalue.
Для собственных классов компилятор такого запрета не вставляет автоматически: выражение `c1 + c2` — это временный объект типа `C`, а он умеет присваивание.

**Решение** — сделать возвращаемое значение `const`:

```cpp
const C operator+(const C& x, const C& y) {
    // ...
}
```

Теперь `c1 + c2 = 5;` — ошибка компиляции (присваивать не во что).

### 1.4. Арифметические операторы

Операторы `+ - * / % & | ^` перегружаются аналогично `+`.

Операторы `<<` и `>>` — это и побитовые сдвиги, и вывод (ввод) в поток. В качестве стримовых их определяют **вне класса**: левым операндом является поток, а не `this`.

### 1.5. Операторы потоков `<<` и `>>`

Чтобы писать `cout << c`, оператор должен возвращать **ссылку на поток** — тогда работает цепочка `cout << a << b`.

Тип потока: `std::ostream` (`o` — output, `stream` — поток).

```cpp
std::ostream& operator<<(std::ostream& out, const C& c) {
    out << ...;      // печатаем содержимое c
    return out;      // для цепочки
}

std::istream& operator>>(std::istream& in, C& c) {
    in >> ...;       // читаем в c
    return in;
}
```

Замечания:

- `const` у параметра-потока **не нужен**: внутреннее состояние потока может меняться;
- объект `c` в `>>` передаётся **по ссылке без const** — в него пишут;
- `>>` не может быть member-функцией класса (левый аргумент — поток, не `this`), поэтому выносится за класс; если ему нужен доступ к приватным полям — объявляется **`friend`**.

### 1.6. Операторы сравнения

Принятый порядок: основную логику кладут в один оператор (обычно `<`), остальные выражают через него:

```cpp
bool operator<(const C& c) const {
    // основная реализация
}

bool operator>(const C& c) const {
    return c < *this;
}

bool operator<=(const C& c) const {      // "не больше"
    return !(*this > c);
}

bool operator>=(const C& c) const {      // "не меньше"
    return !(*this < c);
}

bool operator==(const C& c) const {
    return !(*this < c) && !(c < *this);
}

bool operator!=(const C& c) const {
    return !(*this == c);
}
```

> Примечание: с C++20 эту «заготовку» можно заменить одним оператором трёхстороннего сравнения `operator<=>` («космолёт») — остальные сгенерирует компилятор.

### 1.7. Инкремент и декремент: `++i` и `i++`

**Префиксный `++i`** — возвращает **ссылку**, никаких копий не создаётся. Метод **не const**, потому что меняет объект:

```cpp
C& operator++() {
    *this += 1;   // дёшево по памяти: меняем на месте
    return *this;
}
```

Почему `x += 1`, а не `x = x + 1`: второе требовало бы создания копии объекта, т.е. инкремент работал бы за линейное время.

**Постфиксный `i++`** — возвращает **копию** (старое значение), поэтому работает за линейное время (копирует всё число). Отличить его от префиксного можно только **фиктивным аргументом типа `int`**:

```cpp
const C operator++(int) {   // int — фиктивный аргумент, значения не имеет
    C x = *this;            // копия старого значения
    *this += 1;
    return x;
}
```

Сравнение:

| | `++i` (префиксный) | `i++` (постфиксный) |
|---|---|---|
| Возвращает | `C&` — ссылку | `const C` — копию (rvalue) |
| Сложность | O(1) | O(n) — копирует весь объект |
| Результат | lvalue: `++c = 5` формально скомпилируется (хотя это бред) | rvalue: `c++ = 5` — ошибка компиляции |

`--i` и `i--` — аналогично.

### 1.8. Оператор индекса `[]`

Как у строк и динамических массивов — тоже можно перегрузить:

```cpp
class C {
    char* arr;   // поле

public:
    // неконстантная версия: по индексу можно менять элементы строки
    char& operator[](int i) {
        return arr[i];   // то же, что *(arr + i)
    }

    // константная версия: для константных строк
    const char& operator[](int i) const {
        return arr[i];
    }
};
```

Замечания:

- Возвращаем **ссылку** `char&`, а не `char` по значению: копия не позволила бы менять элемент — `c[0] = 'a';` менял бы уже не то;
- Первый метод **не константный**, даже если явно ничего не меняет: он возвращает **неконстантную ссылку** на internals объекта — через неё объект можно изменить;
- Без второй (const) перегрузки к константной строке нельзя было бы обращаться по `[]`.

### 1.9. Оператор скобок `()` — функторы

Вызов функции — тоже оператор. Объект можно вызывать «как функцию»:

```cpp
C c;
c(1, 12);   // c ведёт себя как функция
```

```cpp
class C {
public:
    bool operator()(const C& a, const C& b) const {
        return a < b;
    }
};
```

Классическое применение — **функция сравнения для сортировки** (например, `std::sort`). Объекты с перегруженным `()` называют **функторами**.

### 1.10. Логические операторы и унарные `*`, `&`, `->`

- `&&` и `||` тоже можно перегрузить;
- унарный `*` — разименование, унарный `&` — взятие адреса: критично для **умных указателей**;
- `->` — обращение к члену через указатель:

```cpp
T* operator->() {
    // ...
}
```

Требование: **возвращаемое значение должно само поддерживать операцию `->`** — это либо указатель, либо тип, у которого есть свой `operator->` (цепочки работают рекурсивно).

**Умный указатель** — объект, который хранит указатель на объект и управляет его жизненным циклом (обычно освобождает память в деструкторе).

### 1.11. Что **нельзя** перегрузить

| Нельзя перегрузить | |
|---|---|
| `.` (точка) | |
| `::` (область видимости) | |
| `.*` и `->*` | |
| `sizeof` | |
| `?:` (трёхместный условный) | |
| `static_cast` | |

Плюс общее правило: **приоритеты операторов изменить нельзя** (помогают только скобки).

Операторы `new` и `delete` перегрузить **можно** (хотя «зачем?» — вопрос лекции).

### 1.12. Операторы преобразования

Объект класса можно превращать в другой тип:

```cpp
class C {
public:
    operator int() {          // тип возвращаемого значения НЕ пишется
        return 42;
    }
};

int x = c;   // неявно вызывается operator int()
```

- Для оператора преобразования тип результата **не указывается** — он и есть название типа: `operator int()`, `operator std::string()` и т.д.
- Неявные преобразования — источник сюрпризов и неоднозначностей; с C++11 можно написать `explicit operator int()`, чтобы преобразование работало только в явных ситуациях (`int x = static_cast<int>(c);`).

## Часть 2. Наследование (Inheritance)

### 2.1. База ООП

Три кита ООП: **инкапсуляция**, **наследование**, **полиморфизм**.

- **Инкапсуляция** — принцип: скрыть реализацию внутри класса.
- Идея ООП: есть типы, есть объекты этих типов, над разными типами поддерживаются разные операции, а программа — это выполнение операций над объектами разных типов.
- При этом некоторые типы могут быть **подтипами** других. Пример: ромб — частный случай параллелограмма, хочется иметь общий тип, который покрывает оба.

### 2.2. Термины

- **Базовый класс** — base, «родитель».
- **Производный класс** — derived, «потомок».

### 2.3. Три вида наследования

```cpp
class Derived : public    Base { ... };   // публичное
class Derived : private   Base { ... };   // приватное
class Derived : protected Base { ... };   // защищённое
```

1. **`public`** — публичное: ни от кого не скрыто, что `Derived` наследуется от `Base`. Внешний код знает об этом и может вызывать public-методы родителя на объектах потомка.
2. **`private`** — приватное: о том, что `Derived` — наследник `Base`, знает только сам `Derived` (и может обращаться к методам родителя). Сторонние функции этого делать не могут.
3. **`protected`** — защищённое: то, что в `Base` объявлено `protected`, видно членам класса, его друзьям (friends) и классам-наследникам.

Как и у полей, существуют три уровня доступа: `public`, `private`, `protected`.

Точнее — как меняются уровни доступа при наследовании:

| Вид наследования | `public` в Base | `protected` в Base |
|---|---|---|
| `public` | → `public` | → `protected` |
| `private` | → `private` | → `private` |
| `protected` | → `protected` | → `protected` |

`private`-члены базового класса никогда не наследуются как доступные.

### 2.4. Какие методы видит объект производного класса

**Ситуация 1.** Потомок добавляет собственные методы — доступны методы из обоих классов:

```cpp
class Base {
    int b;
    void fb();
};

class Derived : public Base {
    int d;
    void fd();
};

int main() {
    Derived d;
    // d.fb() — ок, d.fd() — ок: всё, что public в Base и в Derived
}
```

**Ситуация 2.** В потомке переопределён метод с той же сигнатурой — вызывается версия из потомка:

```cpp
class Base {
    int b;
    void f();
};

class Derived : public Base {
    int d;
    void f();      // переопределение по сигнатуре
};

int main() {
    Derived d;
    d.f();   // вызовется Derived::f()
}
```

**Ситуация 3.** В потомке объявлен метод с тем же именем, но **другой** сигнатурой — **ошибка компиляции**:

```cpp
class Base {
    int b;
    void f();
};

class Derived : public Base {
    int d;
    void f(int x);   // другой список аргументов
};

int main() {
    Derived d;
    d.f();   // ОШИБКА: Base::f() «спрятана»
}
```

Почему ошибка: как только в производном классе появляется имя `f`, **все** одноимённые перегрузки из базового класса перестают видны (поиск имени останавливается на производном классе). Это **затенение** (hiding), а не перегрузка: без `virtual` перегрузка методов по классам в C++ не работает.

> Точность: чтобы базовые перегрузки снова стали видимы, используют директиву `using`:
>
> ```cpp
> class Derived : public Base {
>     using Base::f;     // подтягивает все перегрузки f из Base
>     int d;
>     void f(int x);
> };
> // теперь d.f() снова компилируется
> ```

## Короткая шпаргалка

- Member-оператор → левый операнд = `this`. Если левый операнд «не наш» (`5 + c`, `cout << c`, `cin >> c`) — оператор выносим за класс, при нужде — `friend`.
- `+`, `<` и прочие — реализуем один базовый оператор, остальные через него; бинарные возвращаем `const`/по значению, чтобы запретить `c1 + c2 = 5`.
- `++i` → `C&`, O(1); `i++` → фиктивный `int`, копия, O(n).
- `[]` возвращает ссылку + нужна const-перегрузка.
- `()` делает объект функтором.
- `->` возвращает что-то, что само поддерживает `->` (умные указатели).
- Нельзя перегрузить: `.` `::` `.*` `->*` `sizeof` `?:` `static_cast`; приоритеты не меняются; `new`/`delete` можно.
- Наследование: `public` / `private` / `protected`; одноимённый метод в потомке **затеняет** все базовые перегрузки — противоядие `using Base::f;`.
