> в `<details>`.

---

## Часть 1. Перегрузка операторов

### 1. Оператор можно реализовать в классе и вне его. В чём разница для аргументов?

<details><summary>Ответ</summary>

- **Member-функция:** левый операнд неявно — `this`, аргументов на один меньше, чем операндов.
- **Free-функция (вне класса):** оба операнда — обычные аргументы; часто объявляется `friend`,
  если нужен доступ к приватным полям.

</details>

### 2. Почему `5 + c` нельзя реализовать member-функцией, а `cout << c` — тоже?

<details><summary>Ответ</summary>

У member-оператора левый операнд — всегда `this`, т.е. объект **нашего** класса. В `5 + c` левый
операнд — `5` (`int`), в `cout << c` — поток. Поэтому такие операторы выносятся за класс:
`C operator+(const C& x, const C& y)`, `std::ostream& operator<<(std::ostream&, const C&)`.

</details>

### 3. Почему `5 += c;` невозможно, а `c += 5;` возможно?

<details><summary>Ответ</summary>

Левый операнд `+=` должен быть **изменяемым lvalue** типа с перегруженным `+=`. `5` — константа/rvalue
и у `int` нет механизма «переписать себя», а `c` — наш объект с member-функцией `operator+=`.

</details>

### 4. Почему `c1 + c2 = 5;` компилируется для наших классов, хотя `3 + 4 = 5` — ошибка для `int`? Как запретить?

<details><summary>Ответ</summary>

Для встроенных типов левая часть `=` — rvalue, ошибка. Для наших классов `c1 + c2` — временный
объект типа `C`, а он умеет присваивание; компилятор такого запрета не вставляет сам.
Запрет: вернуть **`const C`** из `operator+` — присваивать в const нельзя.

</details>

### 5. Почему `operator<<` должен возвращать ссылку на поток? Какой у него полный тип?

<details><summary>Ответ</summary>

Чтобы работала цепочка `cout << a << b`: каждый `<<` должен отдать **текущий поток** дальше.
Тип: `std::ostream& operator<<(std::ostream& out, const C& c)` (`o` — output, `stream` — поток).
`const` у потока не нужен (внутреннее состояние меняется), в `>>` объект `c` — по ссылке **без**
`const` (в него пишут).

</details>

### 6. Почему `>>` не может быть member-функцией класса?

<details><summary>Ответ</summary>

Левый аргумент — **поток** (`std::istream`), а не наш объект: member-функция сделала бы левым
оперантом `this`. Поэтому выносится за класс; если нужен доступ к приватным полям — `friend`.

</details>

### 7. Как принято реализовывать операторы сравнения? Приведи, как `==` выражается через `<`.

<details><summary>Ответ</summary>

Основную логику — в один оператор (обычно `<`), остальные — через него:

```cpp
bool operator<(const C& c) const { /* основная реализация */ }
bool operator>(const C& c) const { return c < *this; }
bool operator<=(const C& c) const { return !(*this > c); }
bool operator>=(const C& c) const { return !(*this < c); }
bool operator==(const C& c) const { return !(*this < c) && !(c < *this); }
bool operator!=(const C& c) const { return !(*this == c); }
```

В C++20 эту заготовку заменяет `operator<=>` («космолёт»).

</details>

### 8. Чем отличаются по реализации `++i` и `i++`? Как формально отличить постфиксный?

<details><summary>Ответ</summary>

| | `++i` | `i++` |
|---|---|---|
| Возвращает | `C&` — ссылку | `const C` — копию (старое значение) |
| Сложность | O(1) | O(n) — копирует объект |
| `x++ = 5` | — | ошибка (rvalue) |

Постфиксный отличают **фиктивным аргументом `int`**: `const C operator++(int)`.

</details>

### 9. Почему в `operator++` пишут `*this += 1`, а не `*this = *this + 1`?

<details><summary>Ответ</summary>

Вторая форма создаёт копию объекта (`*this + 1`) — инкремент работал бы за линейное время.
`+=` меняет **на месте** — O(1) (плюс цена самого `+=`).

</details>

### 10. Почему `operator[]` возвращает `char&`, а не `char`?

<details><summary>Ответ</summary>

Чтобы можно было **менять** элемент: `c[0] = 'a';`. Возврат по значению дал бы временную копию —
присваивание бы «пропало». Плюс нужна **const-перегрузка** `const char& operator[](int) const`,
иначе к константной строке нельзя было бы обращаться по `[]`.

</details>

### 11. Почему неконстантная перегрузка `operator[]` не может быть `const`-методом?

<details><summary>Ответ</summary>

Он возвращает **неконстантную ссылку** на внутренние данные — через эту ссылку объект можно
изменить. `const`-метод обещает «не меняю состояние» (в том числе через доступ к internals),
поэтому такой метод помечать `const` нельзя.

</details>

### 12. Что делает перегрузка `()`? Какое классическое применение?

<details><summary>Ответ</summary>

Позволяет вызывать объект как функцию: `C c; c(1, 12);`. Объекты с перегруженным `()` называют
**функторами**; классическое применение — функция сравнения для `std::sort`.

</details>

### 13. Какое требование к возвращаемому значению `operator->`? Зачем это для умных указателей?

<details><summary>Ответ</summary>

Возвращаемое значение должно **само поддерживать `->`**: указатель, либо тип со своим
`operator->` (цепочка работает рекурсивно). Умный указатель хранит сырой указатель и управляет
жизненным циклом (освобождает память в деструкторе) — `->` даёт доступ к членам объекта.

</details>

### 14. Перечисли, что **нельзя** перегрузить. А что можно, но «зачем?»

<details><summary>Ответ</summary>

Нельзя: `.`, `::`, `.*`, `->*`, `sizeof`, `?:`, `static_cast`. Плюс приоритеты операторов не меняются
(помогают только скобки). **Можно** перегрузить `new` и `delete` (зачем — вопрос лекции).

</details>

### 15. Как устроен оператор преобразования? Почему тип результата в нём не указывается?

<details><summary>Ответ</summary>

```cpp
class C { public: operator int() { return 42; } };
int x = c;   // неявный вызов
```

Тип результата и **есть** название: `operator int()`. Неявные преобразования — источник сюрпризов,
поэтому с C++11 можно `explicit operator int()` — тогда только явные ситуации:
`int x = static_cast<int>(c);`.

</details>

## Часть 2. Наследование

### 16. Назови три кита ООП и сформулируй инкапсуляцию.

<details><summary>Ответ</summary>

Инкапсуляция, наследование, полиморфизм. **Инкапсуляция** — скрыть реализацию внутри класса:
внешний код видит только интерфейс, а не внутренности.

</details>

### 17. Что такое базовый и производный класс? Приведи пример подтипов.

<details><summary>Ответ</summary>

**Базовый** — base, «родитель»; **производный** — derived, «потомок». Пример: ромб — частный
случай параллелограмма; хочется общий тип, покрывающий и ромб, и параллелограмм.

</details>

### 18. Чем отличаются `public`, `private` и `protected` наследование?

<details><summary>Ответ</summary>

- `public` — все знают, что `Derived` наследуется от `Base`; внешний код может вызывать public-методы родителя.
- `private` — о том, что `Derived` — наследник, знает только сам `Derived` (может обращаться к методам родителя); сторонние — нет.
- `protected` — то, что в `Base` объявлено `protected`, видно членам класса, friends и классам-наследникам.

</details>

### 19. Как меняется доступ `public` и `protected` членов базы при трёх видах наследования?

<details><summary>Ответ</summary>

| Вид | `public` в Base | `protected` в Base |
|---|---|---|
| `public` | → `public` | → `protected` |
| `private` | → `private` | → `private` |
| `protected` | → `protected` | → `protected` |

`private`-члены базы никогда не наследуются как доступные.

</details>

### 20. В потомке объявлен `void f(int)`, а в базе — `void f()`. Что будет при `d.f()`? Почему?

<details><summary>Ответ</summary>

**Ошибка компиляции.** Как только в `Derived` появляется имя `f`, **все** одноимённые перегрузки из
`Base` перестают быть видны — это **затенение (hiding)**, а не перегрузка. Без `virtual` перегрузка
методов «между классами» не работает.

</details>

### 21. Как вернуть видимость базовых перегрузок в производном классе?

<details><summary>Ответ</summary>

Директива `using` в теле класса:

```cpp
class Derived : public Base {
    using Base::f;     // подтягивает ВСЕ перегрузки f из Base
    void f(int x);
};
// теперь d.f() снова компилируется
```

</details>

### 22. В двух словах: почему `const` после `)` в объявлении member-оператора важен?

<details><summary>Ответ</summary>

Позволяет вызывать метод из **константного** объекта — метод обещает не менять состояние.
Без `const` его нельзя вызвать через `const C&`.

</details>
