# Лекция 5. Классы, перегрузка операторов — вопросы для практики

> Составлено по `final_readme.md`. Как заниматься: бери вопрос, сначала формулируй ответ вслух (или в голове),
> потом раскрывай `<details>` и сверяйся. Цель — отвечать без заглядывания.

## Базовое: `this`, `.` и `->`

### 1. Чем отличаются `.` и `->`? Запиши, что скрывается за `p->f()`.

<details><summary>Ответ</summary>

- `.` — обращение к члену **объекта**: `s.f()`.
- `->` — обращение к члену через **указатель** на объект.
- `p->f()` — это сокращённая форма `(*p).f()`: сначала разименование, потом вызов метода.

</details>

### 2. Что такое `this`? Всегда ли его нужно писать?

<details><summary>Ответ</summary>

`this` — указатель на объект, в котором выполняется метод. Писать **не обязательно** — нужно только при
конфликте имён (имя поля совпадает с именем аргумента): `this->str = s;`. В `for (int i = 5; i-->0; ...)`
никакого `-->` нет — это `i--` и `>`, слитые вместе.

</details>

### 3. Почему `p->f()` и `(*p).f()` — одно и то же?

<details><summary>Ответ</summary>

`->` — синтаксический сахар над «разименование + точка»: компилятор превращает `p->f()` в `(*p).f()`.
Никакой семантической разницы нет, только удобство чтения.

</details>

## Оператор присваивания `=`

### 4. Что сгенерированный по умолчанию `operator=` делает с классом, содержащим `char* str`? В чём беда?

<details><summary>Ответ</summary>

Поверхностное копирование: копирует только указатель. В итоге:

1. старый массив исходного объекта не освобождён → **утечка памяти**;
2. два объекта указывают на один и тот же массив → **двойное освобождение** в деструкторах.

</details>

### 5. Почему `operator=` обязан возвращать **ссылку**? Что сломается, если вернуть по значению?

<details><summary>Ответ</summary>

Ради цепочного присваивания: `x = y = z;` читается как `x = (y = z)`. Внутреннее `y = z` должно дать
объект, которому можно присвоить — т.е. lvalue. Возврат по значению даёт временный (rvalue) →
цепочка не скомпилируется (или будет работать «не в то место»).

</details>

### 6. Зачем в `operator=` сначала проверяем `&s == this`? Что произойдёт при `s = s` без проверки?

<details><summary>Ответ</summary>

Без проверки при `s = s`:

1. `delete[] str;` — старый массив удалён;
2. `str = new char[s.size];` — копируем массив **из самого себя**, но данные уже удалены → UB.

Поэтому первая строка любого `operator=` — защита от присваивания самому себе.

</details>

### 7. В правильной реализации `operator=` каков порядок действий?

<details><summary>Ответ</summary>

1. `if (&s == this) return *this;` — защита от самоприсваивания;
2. `delete[] str;` — освободить старую память;
3. `str = new char[s.size];` — выделить новую;
4. скопировать содержимое;
5. `return *this;` — для цепочки.

</details>

### 8. Сформулируй Rule of 3. Как правило меняется в C++11 (Rule of 5)?

<details><summary>Ответ</summary>

**Rule of 3:** если классу нужен хотя бы один из — деструктор, конструктор копирования, `operator=` —
нужно писать **все три**.

**Rule of 5 (C++11):** к тем же трём добавляются move-конструктор и move-присваивание.

</details>

## Инициализация и конструкторы

### 9. Почему `const int x` и `int& y` нельзя инициализировать присваиванием в теле конструктора? Что делать?

<details><summary>Ответ</summary>

К моменту входа в тело `{}` поля **уже должны быть инициализированы**; константе и ссылке присваивать
нельзя. Решение — **список инициализации**: `C(const int x, int& y) : x(x), y(y) {}`.

</details>

### 10. В каком порядке инициализируются поля — по порядку объявления в классе или по порядку в init-list?

<details><summary>Ответ</summary>

По **порядку объявления полей в классе**, независимо от порядка в списке инициализации.
Если написать в init-list не в том порядке — компилятор может предупредить.

</details>

### 11. Когда сгенерированный по умолчанию конструктор по умолчанию **не** создаётся?

<details><summary>Ответ</summary>

Среди прочего — если в классе есть `const`-поле или поле-ссылка (без инициализатора при объявлении):
его нужно написать самому, и обязательно со списком инициализации.

</details>

## `explicit`, `const`, `mutable`

### 12. Что делает `explicit`? Приведи пример опасного неявного преобразования.

<details><summary>Ответ</summary>

Запрещает **неявное** преобразование через этот конструктор. Пример: `String s = 5;` — без `explicit`
компилятор сам вызывает `String(int)`. Рекомендация: все конструкторы с одним аргументом — `explicit`.

</details>

### 13. Почему `const String s = "abs"; s.size();` — ошибка, если `size()` не `const`? Как исправить?

<details><summary>Ответ</summary>

Компилятор рассуждает: метод **не обещает** не менять объект, а объект константный → отказ.
Исправление: `int size() const { ... }`. `const` после `)` — обещание не менять состояние объекта.

</details>

### 14. Что такое `mutable`? Для каких полей его применяют?

<details><summary>Ответ</summary>

Позволяет менять поле даже в **константном** объекте. Для полей, изменение которых не меняет логическое
состояние: кэши, счётчики доступов, мьютексы.

</details>

## `friend`, делегирование, `static`, указатели на члены

### 15. Зачем нужен `friend`? Как к нему относиться?

<details><summary>Ответ</summary>

`friend std::ostream& operator<<(std::ostream&, const C&);` — разрешает «посторонней» функции доступ
к приватным полям (нужно, когда оператор не может быть членом класса). Относиться настороженно,
как к C-style cast: ломает инкапсуляцию, друзей не должно быть много.

</details>

### 16. Что такое делегирующий конструктор? Зачем он нужен?

<details><summary>Ответ</summary>

Один конструктор класса вызывает **другой конструктор того же класса**, передавая ему аргументы:
`String::String(const char* s) : String((int)strlen(s), s) { ... }`. Чтобы не дублировать код
инициализации (C++11).

</details>

### 17. Что такое `static`-член класса? Как он объявляется и где определяется?

<details><summary>Ответ</summary>

Одно общее поле/метод **на весь класс**, а не на каждый объект. Объявляется внутри класса,
определяется (инициализируется) снаружи: `int C::x = 0;`. Доступ без объекта: `C::x`.

</details>

### 18. Как объявить указатель на член класса и обратиться к полю через него?

<details><summary>Ответ</summary>

```cpp
int C::* p = &C::a;
obj.*p = 5;    // по объекту
ptr->*p;       // по указателю на объект
```

`::` — проход через область видимости: это член именно класса `C`.

</details>

## Перегрузка `+=` и `+`

### 19. Почему `return *this = *this + x;` внутри `operator+=` — категорически плохо?

<details><summary>Ответ</summary>

Каждый вызов `*this + x` создаёт **копию** объекта (линейное время) и делает лишнее присваивание.
`+=` должен накапливать **по месту** за O(n) без копий; `x = x + y` дорого (копия), `x += y` дёшево.

</details>

### 20. Может ли `operator+=` быть `const`-методом?

<details><summary>Ответ</summary>

Нет. `+=` обязан менять объект — `const`-метод обещает не менять состояние, это ошибка компиляции
(в конспекте запись `+= ... const` помечена как опечатка).

</details>

### 21. Зачем `operator+` реализуют через `operator+=`?

<details><summary>Ответ</summary>

```cpp
C C::operator+(const C& x) const {
    C sum = *this;
    sum += x;
    return sum;
}
```

Логика накопления пишется один раз, `+` — тонкая обёртка: копия + `+=` + возврат по значению.

</details>

### 22. Почему `+` — `const`-метод, а `+=` — нет?

<details><summary>Ответ</summary>

`+` ничего не меняет в обоих операндах — может быть `const`. `+=` меняет левый операнд (`*this`) —
нельзя быть `const`.

</details>

## Быстрые «верю/не верю»

### 23. `String s1 = s;` — что происходит с памятью после этой строки?

<details><summary>Ответ</summary>

Два объекта (если нет своего конструктора копирования) указывают на **один и тот же** массив.
При деструкции — двойное освобождение; старый массив `s` — утечка. Класс с сырым указателем требует
своих copy-конструктора и `operator=`.

</details>

### 24. Верно ли: «указатель — это просто целое число адреса»?

<details><summary>Ответ</summary>

По размеру — да, адрес — целое число (на 64-битной — 8 байт). Но указатель — **типизированная**
переменная с адресом: у неё есть тип указываемого, по нему работают `*` и `+ n` с учётом sizeof.
`*ptr` — значение по адресу, `&ptr` — адрес самого указателя.

</details>

### 25. Что такое «срезка»? (Первый раз встречается здесь, разберётся в 8-й лекции — но попробуй.)

<details><summary>Ответ</summary>

Присваивание `b = d;`, где `d` — производный объект, а `b` — базовый: копируется только базовая
часть, «хвост» производного класса теряется. Связано с поверхностным копированием — той же болезнью,
что и с `operator=` из этой лекции.

</details>
