> Аккуратный конспект лекции Ильи Мещерина по C++.

## 1. Операторы `.` и `->`, ключевое слово `this`

- **`.`** — обращение к полю объекта: `s.str_`.
- **`->`** — обращение к члену через **указатель** на объект (деревья, указатели, связные списки):

```cpp
(*p).f();   // развернуто: разименовать указатель и вызвать метод
p->f();     // то же самое, в сокращённой форме
```

- **`this`** — указатель на тот объект, в котором сейчас выполняется метод.

```cpp
class String {
public:
    String(const char* s, int size) {
        this->str = new char[size];   // this-> нужна, чтобы отличить поле от аргумента
    }
    ~String() { delete[] this->str; }
private:
    char* str;
    int size;
};
```

`this` писать **всегда не нужно** — только при необходимости (когда имя поля совпадает с именем аргумента).

Ловушка: в `for (int i = 5; i-->0; ...)` нет никакого `-->` — это оператор инкремента/декремента `i--` и оператор сравнения `>`, слитые вместе.

## 2. Оператор присваивания `=`

### 2.1. Проблема по умолчанию

```cpp
int main() {
    String s  = String("abc", 3);
    String s1 = s;   // копирование: два объекта указывают на один и тот же массив

    s = s1;           // БЕДА
}
```

Сгенерированный по умолчанию `operator=` — **поверхностное** присваивание: он просто копирует указатель `str`. В итоге:

- память исходного массива **теряется** (утечка памяти);
- два объекта указывают на один и тот же массив (двойное освобождение при деструкции).

То есть без собственной реализации присваивания нас ждут **утечка памяти и ошибки времени выполнения**.

### 2.2. Корректная реализация

Оператор присваивания — это обычный метод; он **обязан возвращать ссылку** на результат (иначе не работал бы цепочный `x = y = 5`):

```cpp
String& String::operator=(const String& s) {
    if (&s == this)          // защита от присваивания самому себе
        return *this;
    delete[] str;            // освободить старую память
    str = new char[s.size];  // выписать новую
    for (int i = 0; i < s.size; ++i)
        str[i] = s.str[i];
    return *this;            // чтобы работал x = y
}
```

Почему нужна проверка `&s == this`. Без неё:

```cpp
String s;
s = s;   // что произойдёт?
```

1. `delete[] str;` — старый массив удалён;
2. `str = new char[s.size];` — копируем массив **из самого себя** — данные уже удалены → Undefined Behavior.

Поэтому в любой реализации `operator=` **первое** — проверка на присваивание самому себе.

Почему возвращаем `*this` по ссылке: из-за цепочного присваивания

```cpp
x = y = 5;   // то же, что (x = (y = 5))
```

### 2.3. Правило трёх (Rule of 3)

> Если классу нужен хотя бы **один** из: деструктор, конструктор копирования, оператор присваивания — нужно писать **все три** вместе.

В **C++11** правило расширяется до **правила пяти**: добавляются оператор перемещения (move-конструктор и move-присваивание).

## 3. Списки инициализации полей в конструкторах

```cpp
class C {
    const int x = 3;   // константное поле
    int& y;            // поле-ссылка
};
```

Здесь **не сгенерируется** конструктор по умолчанию — его нужно написать самому. Но есть проблема:

```cpp
C(const int x, int& y) {
    this->x = x;   // ОШИБКА: нельзя присваивать константе
    this->y = y;   // ОШИБКА: нельзя присваивать ссылке
}
```

К моменту `{` в конструкторе поля **уже должны быть инициализированы**; присваивание `const`/`int&` запрещено. Решение — **список инициализации** (init list), поля инициализируются до входа в тело конструктора:

```cpp
C(const int x, int& y) : x(x), y(y) {}
```

Порядок инициализации — **порядок объявления полей в классе**, а не порядок в списке.

## 4. Вопрос для собеседования: неявные преобразования

```cpp
String s = s1 + 'a';
```

Компилятор пытается неявно преобразовать типы (например, `'a'` → строка → `String`), если у типа есть подходящие конструкторы. Когда у класса много конструкторов, цепочки неявных преобразований ведут к непредсказуемому поведению.

Решение — ключевое слово **`explicit`** (явный; противоположность — implicit, неявный):

```cpp
explicit String(int size) { ... }   // запретит неявное преобразование int → String
```

**Рекомендация:** по возможности объявляйте конструкторы с одним аргументом `explicit`.

## 5. Константные методы

Классический пример — getter:

```cpp
int size() { return size_; }
```

Проблема:

```cpp
const String s = "abs";
s.size();   // ОШИБКА: размерность метода не const
```

Компилятор считает, что метод **имеет право менять** поля объекта `s`, а он константный. Исправление — пометить сам метод как `const`:

```cpp
int size() const { return size_; }
```

`const` после `)` означает: метод является константным **относительно объекта, от которого вызывается** (не меняет его состояние). Это жизненно необходимо — без `const`-методов к константным объектам можно было бы обращаться только к приватным полям через `const_cast`, что безумно.

---

## 6. Ключевое слово `mutable`

```cpp
mutable int x;
```

Позволяет менять поле, даже если **объект константный**. Используется для полей, изменение которых «на самом деле» не меняет логическое состояние объекта (кэши, счётчики доступов, мьютексы).

---

## 7. Ключевое слово `friend`

Иногда оператор или функция не является членом класса (например, `operator<<` для потока), но ему нужен доступ к приватным полям.

```cpp
class C {
    int x;
    friend std::ostream& operator<<(std::ostream&, const C&);  // разрешаем ему доступ
};
```

`friend` — это «я разрешаю этой функции трогать мои приватные поля».

Предостережения:

- **не создавайте много друзей** — за каждый приходится «держать» привилегированный доступ (в памяти и, главное, в архитектуре);
- относитесь к `friend` так же настороженно, как к **C-style cast**: инструмент, который ломает инкапсуляцию.

## 8. Делегирующие конструкторы (C++11)

Есть конструкторы `String(const char*)` и `String(int size, const char*)`, и хочется написать конструктор, который повторяет код старого конструктора, но делает ещё что-то (например, задаёт `capacity`).

До C++11 код пришлось дублировать. Теперь — **делегирование**:

```cpp
String::String(const char* s) : String((int)strlen(s), s) {
    // дополнительный код: capacity и т.д.
}
```

Конструктор делегирует инициализацию другому конструктору того же класса.

## 9. Ключевое слово `static`

Пример: класс с объектами, и нужно **поле, которое не принадлежит ни одному конкретному объекту**:

```cpp
class C {
    static int x;   // одно общее для всех объектов
};
```

`static`-члены класса:

- **один** на весь класс, а не на каждый объект;
- объявляются внутри класса, **определяются (инициализируются) снаружи**: `int C::x = 0;`
- доступны без объекта: `C::x`.

## 10. Указатели на члены (по поля)

Если нужно «объявить указатель на поле»:

```cpp
struct C {
    int a;
    char b;
};

int C::* p = &C::a;        // указатель на член класса C (поле a)
```

Использование:

```cpp
int main() {
    C obj;
    int C::* p = &C::a;

    obj.*p = 5;      // доступ к полю через указатель на член
    // obj ->* p     — то же самое, если у вас указатель на объект

    // :: — проход через область видимости (указывает на член именно класса C)
}
```

## 11. Перегрузка арифметических операторов

Пример с `BigInteger`:

```cpp
BigInteger operator+(const BigInteger& x) const {
    BigInteger sum = *this;
    return sum += x;   // переиспользуем +=
}
```

**Правильная** `+=` накапливает в месте:

```cpp
BigInteger& operator+=(const BigInteger& x) {
    // ... накапливаем x в *this по месту, O(n)
    return *this;
}
```

**Как писать НЕЛЬЗЯ:**

```cpp
BigInteger& operator+=(const BigInteger& x) {   // const здесь — уже ошибка
    return *this = *this + x;                   // КАТЕГОРИЧЕСКИ НЕЛЬЗЯ!!!
}
```

Почему:

1. Каждый вызов `*this + x` — это создание **копии** BigInteger — линейное время;
2. В итоге сложение `x += y` работает за **линейное время** на каждый шаг, а не за постоянное;
3. `x = x + 1` — дорого (копия), `x += 1` — дёшево (по месту).

> Замечание: в исходных заметках `+=` помечен как `const` — это опечатка: `operator+=` **не может** быть `const`, он обязан менять объект; `const` здесь — ошибка компиляции.

## Короткая шпаргалка

- `.` — по объекту, `->` — по указателю; `this` — указатель на текущий объект (пишем не всегда, а при конфликте имён).
- `operator=` — поверхностное копирование указателя → утечка + двойное освобождение. Пишем сами: проверка `&s == this`, `delete[]`, новое выделение, возврат `*this`.
- **Rule of 3** (C++03) / **Rule of 5** (C++11): деструктор, конструктор копирования, `=` (в C++11 + move-конструктор и move-присваивание) — либо все, либо никто.
- `const`/ссылка-поле — только через **список инициализации** `C(...) : x(x), y(y) {}`.
- `explicit` на конструкторах с одним аргументом — защита от неявных преобразований.
- Методы, которые не меняют объект — с `const`; поле, которое можно менять в константном объекте — `mutable`.
- `friend` — доступ к приватным полям из «посторонних» функций; использовать осторожно, как C-style cast.
- **Делегирующий конструктор** (C++11) — один конструктор вызывает другой того же класса.
- `static`-поле — общее для всех объектов класса, инициализируется снаружи.
- Указатель на член: `int C::* p = &C::a;`, доступ `obj.*p` или `ptr->*p`.
- `operator+=` — накапливать **по месту**, не писать `*this = *this + x` (линейное время на каждое сложение).
