5.б) спецификации исключений (начиная с 11)

noexcept

спецификатор, это слово, которое можно написать перед открывающей скобкой в методе

void f(..., ) noexcept() {
    throw 1;
}

если функция f содержит внутри себя throw, то я получу не runtimeerror а "ошибку компиляции"

но что если: в f  я хочу пользоваться другими функциями и по поводу других не понятно, есть ли в них исключение или нет

void f(T x) noexcept() {
    throw 1;   g(x); // версия для x int -> исключение, остальные ок
}

для этого нужен оператор noexcept() он возвращает true/false и теперь можно написать


void f(..., ) noexcept(noexcept(g(x))) {
    throw 1;  g(x);
}

noexcept(g(x)) - это выражение

пусть, и нужно вычислить fib(10)
noexcept(fib(10) > 200 ? 1 : 0);
это просто не скомпилируется, но не в C++14

6) Исключения в констуркторах
class Мещерин пишет по привычке (на работе так) но на лекции из-за лени
пишет struct

struct Ugly {
    int* p;
    Ugly() {
        p = new int;
        throw 1;
    }
    ~Ugly {
        delete p;
    };
}

int main() {
    try {
        Ugly u;
    } catch (...) {}
}

что здесь происходит? утечка памяти, потму что в констукторе new и delete никто не 
сделает
